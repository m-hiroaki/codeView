# 03 ファイル・文字コード・ツリー

[索引](README.md) / 共通：[契約](01-contracts.md) / 上位：基本設計4.1・4.2・5章

## 1. 内部契約

| 型・配置 | 設計上のメソッド | 責務 |
| --- | --- | --- |
| `ISourceAccess` / Files | `OpenRead`、`GetStamp`、`InspectPath`、`ResolveDirectory`、`EnumerateChildren` | OS差と読取I/Oの試験境界。同期入口はワーカー専用。書込メソッドなし |
| `SourceAccess` / Files | 上記の具体実装 | 通常ファイル確認・リンク確認・ストリーム・メタデータ |
| `FileReader` / Files | `PrepareAsync(path, encodingChoice, ct)`、`ReadChunksAsync(prepared, consume, ct)`、`ReadChunks(prepared, consume, ct)` | 厳格な文字コード準備と逐次読込。同期版もUI外の本文構築用に限る |
| `PreparedText` / Files | 選択文字コード、判定情報、SourceStamp、現在の読取資源 | 呼出元セッションが所有し、終了時に破棄する |
| `DirectoryReader` / Files | `InspectPathAsync`、`ResolveRootAsync`、`ReadChildrenAsync(folder, policy, ct)`、`WalkFiles(root, policy, ct)` | 入力種別確認、ツリー直下列挙とワーカー上の検索用逐次列挙 |
| `ExclusionPolicy` / Files | `IsExcludedDirectory(name)`、`IsSearchTarget(entry)` | スナップショット化した名前リストとリンク規則 |
| `SourceEntry` / Files | 指定パス・名前・Directory/FileCandidate/Other・リンク有無 | UI型を含まない列挙時点の情報。FileCandidateの通常ファイル確認はOpen境界で行う |
| `DirectoryListing` / Files | 直下の読取専用一覧、Error、IsComplete | 部分一覧と失敗を同時に保持。空の成功と失敗を区別する |
| `DirectoryWalkEvent` / Files | File/SkippedLink/SkippedDirectory/SkippedSpecialEntry/Failed、パス・エラー・ルート失敗フラグ | 全件保持せず逐次処理する。エラー代表例の上限は消費側が管理 |

列挙・検証もI/OなのでUI上で実行しない。ReadChunksAsyncのconsumeは`ValueTask`相当の非同期コールバックで、借用チャンクの寿命は呼出から完了までに限定する。読み取り途中で例外が出ればPreparedTextを使い回さない。

DirectoryReaderのルート解決・直下取得はTask.Runのワーカーへ送る。OSのディレクトリ列挙は同期APIなので、検索用WalkFilesは外側の検索ワーカーで列挙する同期IEnumerableとする。各項目にTaskやUI通知を作らない。列挙開始は最初のMoveNextで、呼出元のforeachを正常・取消・途中終了のいずれでも破棄する。本文ライブラリやUIに依存しないFiles部分はG2採否前に検証できるが、これを本文採用やツリーUIの完了としない。

## 2. パス・リンク・共有アクセス

1. 空・不正なパスは入口で拒否し、相対パスを固定基準から絶対化する。Unicode変換・文字列の一律小文字化はしない。
2. 種類を確認し、デバイス・ソケット・パイプ等を拒否する。判定とOpen間の競合はOpen時にも検査する。
3. 明示Openのファイルリンクは解決し、通常ファイルなら読む。指定パスはタブID用、解決先は補助表示・読取判定に使う。循環・リンク切れは失敗にする。
4. 検索列挙はファイルリンク・フォルダリンク・ジャンクションを追わない。指定したルート自体がリンクなら最初に明示解決し、その内部のリンクを追わない。
5. 読取専用で開き、対応OSでは外部の読取・書込・削除を妨げない共有モードを候補とする。実際の置換・削除挙動は両OSで試験する。

初期実装ではUI外の同期入口`SourceAccess.OpenRead`と`FileReader.Prepare / ReadChunks`を使用する。macOSは`O_NONBLOCK | O_CLOEXEC`で開いたハンドルを`fstat`で確認し、FIFOが書込相手を待つ前に拒否する。Windowsは読取専用ハンドルとGetFileTypeで通常ディスクファイルを確認する。Darwinの定数・stat64レイアウト・x64のINODE64シンボルは[Appleのヘッダー](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/sys/stat.h)と同梱SDKで確認する。OS依存はSourceAccess内に限定し、実機で確認していないCPUを検証済みとしない。

SettingsStoreも特殊ファイルの安全な読取確認に同じ境界を利用する。ファイルリンクの更新情報は解決先から取得し、リンク自体の長さを本文サイズと誤認しない。厳格デコードの非同期返却は検索接続時に実装し、同期入口をUIから直接呼ばない。

同一パスのタブ判定は、正規化した指定パスのOrdinal一致を基本とし、大文字小文字が異なる別名についてはOSのファイル同一性確認が得られた場合だけ統合する。大文字小文字だけを無条件に無視しない。リンク・ハードリンクの別名を完全に統合しない。OS問い合わせが必要ならワーカーで行い、UI上でパス解決をしない。

## 3. バイナリと文字コードの準備手順

厳格なデコードを共通化し、拡張子だけでは表示可否を決めない。初期案は読み取り用の同一ハンドルを保持して巻戻せる通常ファイルを対象とする。

1. SourceStampを取得し、先頭最大8 KiBを読む。0バイトはUTF-8の空本文とする。
2. 最長BOMからUTF-32 LE・BE、UTF-8、UTF-16 LE・BEを識別する。BOMは本文に含めない。
3. PNG、JPEG、GIF、PDF、ZIP、PE、ELF、Mach-O等の確実なシグネチャを判定する。形式一覧と誤検出データは試験で固定する。手動指定でも明確なバイナリは拒否する。
4. BOMがあればその文字コード、手動指定があれば指定を候補とする。手動指定と矛盾するBOMは黙って無視せず、BOMの文字コードで開く案内を返す。
5. BOMも指定もなければNULの有無と制御バイト分布を調べる。初期閾値はNULが1つ以上、または許可した改行・タブ・フォームフィード以外のC0制御バイトが標本の1%を超える場合をバイナリ疑いとする。
6. バイナリ疑いなら拒否通知と文字コード指定による再試行を可能にする。BOMなしUTF-16等の誤判定を完全に防ぐとは扱わない。
7. 自動の最初の候補は厳格なUTF-8。末尾まで分割して妥当性を確認し、失敗ならCP932を厳格に検証する。両方失敗はDecodeFailed。CP932初期化は最初の利用時だけ行う。
8. BOMまたは手動指定も、同様に末尾まで厳格検証する。検証後にStampを比較し、変化があればChangedDuringRead。
9. 成功時は巻戻してBOMを除き、PreparedTextとして渡す。本文構築・検索は同じ選択で読み、末尾までデコードと更新を再確認する。

制御文字の閾値は測定開始値であり、Unicodeの制御文字分類による判定と混同しない。UTF-8・CP932が両方成立する曖昧な入力はUTF-8を優先し、自動判定の限界と手動選択を提供する。判定失敗を置換文字で隠さない。

PE判定はMZの2バイトだけでは行わない。先頭に64バイト以上あり、DOSヘッダーの0x3c位置にあるファイルオフセットが64以上・ファイル内で、そこに`PE\0\0`の4バイト署名がある場合に既知バイナリとする。署名全体が8 KiB標本にあれば再読込せず、標本外/標本境界をまたぐ場合だけ同じ読取ハンドルで4バイトを追加取得する。破損したオフセットによる大きなバッファ確保は行わない。追加読取後もデコード検証と消費読込はそれぞれ先頭へ戻す。形式の完全な正当性検査や実行可能性の検査は行わない。参照：[Microsoft PE形式のDOS stubと署名](https://learn.microsoft.com/en-us/windows/win32/debug/pe-format#ms-dos-stub-image-only)。

## 4. 事前検証のI/Oと整合性

検索途中にUTF-8からCP932へ切替えて、既に表示した位置が別のデコード結果になることを避けるため、初期方式は文字コードを確定する検証パスと、消費する読込パスを分離する。全文をメモリへ退避しない。一方、UTF-8では通常2回、CP932への再試行では最大3回程度の全走査を要し、巨大リポジトリの速度を下げる可能性がある。

これはD-06の必須評価項目とし、Cold / Warmの実I/OとデコードCPUを測る。未達時は、ファイル単位の仮結果と失敗時の取消・再検索など代替を比較し、正確性・資源・表示仕様への影響を示してから方式を変更する。事前検証を理由に本文を全件キャッシュしない。

2回目の読込中も外部更新は可能であり、一貫したスナップショットは保証しない。読取失敗・不正バイト・更新検出があれば当該ファイルを未評価扱いにし、既に返した当該ファイルの結果は無効化する。[05](05-search.md)のファイル単位無効化通知を使う。同サイズ・同更新日時の置換を完全には検出できない。

2026-10-31のL1 Warm評価で、各検証/消費に64 KiB設定のStreamReaderを作る方式は合計割当約24.9 GiB・GC停止約2.35秒となり予算を超えた。検証と消費を共通のDecoder.Convertループへ変更し、各実行でバイト64 KiB・文字16 Ki UTF-16単位をArrayPoolから借りる。先頭標本8 KiBも借用する。ファイル数・ファイル全体のサイズに比例するプール確保は行わない。

Decoderはパス/検証ごとに新しく作り、UTF-8からCP932への再試行や別ファイルへ状態を持ち越さない。入力の残りがある間はConvertを繰り返し、EOFでflush=trueにして不完全な末尾を厳格に拒否する。検証では文字を外へ出さず、消費では最大16 Ki単位の借用メモリを同期通知する。通常・取消・デコード/I/O/利用側例外の各終了経路でfinallyからプールへ一度だけ返し、clearArray=trueで再利用前の内容消去を指定する。PreparedTextやコールバックからバッファを所有し続けない。

この変更は割当対策であり、事前検証・巻戻し・SourceStamp再確認を省略せず、追加I/Oが必要な方式自体の採否も変えない。FileStreamの既存バッファ設定は維持する。参照：[Decoder.Convert](https://learn.microsoft.com/en-us/dotnet/api/system.text.decoder.convert?view=net-10.0)、[ArrayPool.Return](https://learn.microsoft.com/en-us/dotnet/api/system.buffers.arraypool-1.return?view=net-10.0)。

## 5. デコード・行情報

- バイトチャンク間でDecoderの未完文字を持ち越し、各チャンクを別々の文字列として解釈しない。
- デコーダー終端の不完全バイトは厳格な失敗とし、黙って切り捨てない。
- CRLFが文字チャンク境界をまたぐ場合はCRを保留し、1改行として確定する。
- UTF-16オフセット・行番号・列をlongで加算し、桁あふれを検出する。サロゲートはチャンク端で保留できるようにする。
- 通常検索用に行全体を無制限に組み立てない。必要な抜粋と照合の文脈だけを保持する。正規表現用の行は05の上限を適用する。
- PreparedTextはファイル全内容を持たず、ハンドル・選択文字コード・BOM長・Stampを持つ。Decoderと固定バッファは検証/消費の各呼出が所有し、終了・取消・失敗時に返却する。

## 6. 直下ツリーの列挙

`TreeNodeState`はOperations内でPath、種別、`NotLoaded / Loading / Loaded / Failed`、子一覧、列挙世代を持つ。ViewModelはこの状態を表示へ写し、UI部品に子孫全体を先に作らない。

1. 展開時、Loadedなら再利用、Loadingなら要求を集約し、その他は新しい列挙世代で開始する。
2. 直下だけをワーカーで列挙し、除外名を適用する。フォルダリンクは表示するが自動展開しない。
3. 初期はフォルダ先、次にファイルとし、各群はOrdinalIgnoreCase、同順位はOrdinalで名前順にする。並び順はパス同一性の判定とは別にする。
4. 並び替えが終わった論理ノードを小分けにUIへ反映する。ルート・ノード世代を各バッチで確認する。
5. 空はLoadedの空一覧。失敗はFailedとして再試行を許可する。途中失敗は部分一覧と明示し、再展開で成功扱いにしない。

再読込操作は子一覧の世代を更新し、旧結果を破棄する。折りたたみは表示を外し、要求が不要なら取消する。折りたたみ済み子一覧はLRU順に破棄し、CollapsedCacheNodesの上限を守る。開いたタブはツリーノードを所有せず、ツリー破棄で本文が閉じない。

### 6.1 Operations内の状態と寿命

`WorkspaceState.Tree`が`TreeSession`を所有し、ルート直下の確認結果から初期論理ノードを作る。TreeSessionはUI型や本文型を参照せず、`ExpandAsync(node, reload)`、`Collapse(node)`、`Dispose`、`PendingWork`を持つ。TreeNodeStateはSourceEntry、子一覧、状態、展開有無、世代、失敗、所属セッション/接続有無を保持する。ルートの再読込はWorkspaceの操作から行い、TreeSession内の再読込対象は子フォルダとする。

同じLoadingノードへの通常展開は同じTaskを返す。Loadedは再利用し、Failedは部分一覧があっても再列挙する。リンク/ファイルは展開を拒否する。切り離されたノードと終了済みセッションの要求は取消済みとして扱い、別セッションのノード指定はプログラミングエラーとする。再読込はそのノードと子孫の旧要求・旧一覧を無効化する。

ツリー枠1はルート解決/列挙と子列挙で共有する。待機は既定64要求、実行中は最大1要求。同じノードの集約を先に判定し、上限に達した新規要求はQueueFullで拒否してノード状態を変えない。取消済みでも継続処理が終わっていない物理的な待機Taskを予算に数え、連続展開/折りたたみで待機数が無制限にならないようにする。

折りたたみでは当該要求と子孫の要求を取消し、孫以下の一覧を破棄する。当該ノードの直下だけをLRUキャッシュに残し、キャッシュ内の直下ノード数合計を10,000以下にする。一覧単体で上限を超える場合はその一覧も破棄する。再展開による利用時はキャッシュから外し、再度折りたたんだ時に最新の利用順へ入れる。空のLoadedは追加ノードを保持しないためキャッシュ件数0でも再利用できる。破棄は明示スタックで処理し、深い階層で再帰呼出を増やさない。

ルート切替/閉鎖時は旧TreeSessionをDisposeし、全要求を取り消して一覧を外す。取消不能I/OはTask完了まで枠を保持する。AppOperationsは旧セッションのPendingWorkも終了待ちへ引き継ぎ、ViewModelのPendingWorkに含める。結果採用はルート寿命Token、ノード所属/接続、展開有無、ノード世代をすべて確認する。予期しない例外はFailed/Unexpectedを記録して上位へ伝え、空の成功に変換しない。

この責務をAppOperationsに直書きするとノード別要求・キャッシュ管理まで集中するため、同じOperations内の専用クラスへ分ける。利点はUIや本文モデルを起動せず取消/上限を試験できること、不利点はWorkspaceとセッションの終了待ち接続が増えること。影響はOperationsの内部状態と終了時の待機に限定し、層・依存方向・Contractsは変えない。論理状態と単体試験→表示への小分け反映→仮想化・実機性能の順で接続し、既存の本文やルート入力処理を置換しない。

### 6.2 表示行と仮想化

PresentationのFileTreeViewModelは展開中の論理ノードだけを、親行・深さを持つFileTreeRowへ投影する。未展開の子孫を行へ変換しない。RowsはAvaloniaListで、初期直下/子展開を最大256行または行生成4msごとのバッチでInsertRangeし、未反映分があればBackground優先度のDispatcher.Yieldを挟む。通知・レイアウトの実時間は4msを保証するものではなく、実機で別に評価する。

各バッチでルートの表示世代、ノード接続/展開有無、列挙世代、投影世代を確認する。別の枝の展開が割り込んでも最後に挿入した兄弟の子孫の後から続きを挿入し、名前順を崩さない。折りたたみは当該枝だけをRemoveRangeし、他枝の行オブジェクト・選択を維持する。隠れる子が選択されていた場合は折りたたんだ親を選択する。ルート変更/終了は全表示行を外す。表示反映TaskもViewModelの終了待ちに含める。

仮想化は平坦なListBoxと明示したVirtualizingStackPanelで行い、高さ制約のあるGrid内に置く。各行は28pxで、階層は余白で示す。展開された論理行の配列は保持するが、全行のUIコンテナを常時生成する構造にはしない。階層型コンテナを再帰生成しない利点がある一方、親移動/枝ごとの挿入位置/選択はPresentationで扱う必要がある。影響は表示行とUIだけで、Operationsの論理ツリー・Files・本文契約は変えない。論理投影の単体試験とXAMLコンパイル→実機のコンテナ実現数/スクロール/メモリ・アクセシビリティ確認の順で検証する。

矢印クリックは展開/折りたたみ、行ダブルクリックまたはEnterはフォルダの展開状態を切り替えるか、ファイルを開く。ダブルクリックはポインター直下の行に適用し、一覧の余白や展開ボタンの上では行操作を実行しない。右キーは展開、左キーは折りたたみまたは親行選択。F5/再読込ボタンは選択フォルダを再列挙し、通常フォルダ未選択ならルートを再読込する。ファイルOpen成功後は本文へフォーカスを移す。読込中・空・失敗・部分失敗・リンクは行に区別して示し、QueueFullはツリー上の通知で再試行を案内する。表示メニューでツリーを隠しても本文と論理状態は保持する。

参照：[ListBox](https://docs.avaloniaui.net/controls/data-display/collections/listbox)、[AvaloniaList](https://api-docs.avaloniaui.net/docs/T_Avalonia_Collections_AvaloniaList_1)、[UIスレッド](https://docs.avaloniaui.net/docs/app-development/threading)。採用版12.1.3のXML文書でもInsertRange/RemoveRange/Dispatcher.Yieldを確認する。実機での入力・コンテナ実現数・直下大量表示は未確認であり、単体投影試験だけでFT-04/P3-03を完了としない。

直下の並び替えは直下項目数に比例するメモリを使う。検索用の全階層パス保持と同一視しない。直下大量構成で予算を超えた場合は部分表示・並び替え方式を評価し、無断で無制限保持へ拡大しない。

列挙はHidden/Systemを属性だけで黙って除外せず、共通の名前ポリシーを適用する。ディレクトリリンクは表示情報として返すが、直接の直下列挙では拒否する。利用者がルートとして明示指定する場合だけResolveRootAsyncで最終ターゲットを解決し、指定パスは呼出側のWorkspaceに保持して解決先を列挙する。リンク化の競合は入場時にも再確認するが、基本設計どおり外部更新を完全に防ぐサンドボックスとはしない。

## 7. 検索対象の逐次走査

深さ優先で、現在階層の列挙器と戻り先だけを保持する。各階層で子一覧を配列化したり全ファイルをソートしたりしない。列挙器は進入時に作り、退出時に必ず破棄する。深い階層は再帰メソッドのスタックに任せず、明示的なフレーム列で扱う。

除外名は`.git`、`bin`、`obj`、`node_modules`が既定で、完全なフォルダ名に適用する。大小文字比較は対象ファイルシステムの規則に従い、判定できない場合は完全一致とする。設定リストを処理開始時に固定する。globや`.gitignore`解釈は導入しない。

権限不足は当該枝をスキップして件数と上限付き代表例を記録し、別の枝を続ける。ルート自体が読めない場合は全体失敗。リンクは追わず、ハードリンクは重複排除しない。全件数を調べる前走査・深さ制限による黙った打切り・常駐索引は行わない。

WalkFilesは明示的な列挙フレームのスタックを持つ。想定内のI/O/権限例外はFailedイベントにし、取消はOperationCanceledException、予期しない例外はそのまま上位へ伝える。いずれも全フレームをfinallyで破棄する。子の失敗後は兄弟を継続し、ルート自身の失敗にはIsRootを付けて正常完了と区別する。FileCandidateは列挙上の候補であり、FIFO等が属性だけでは区別できないOSでも本文Open時の通常ファイル検査で拒否する。

ExclusionPolicyは名前集合を複製し、既定はOrdinal完全一致とする。OrdinalIgnoreCaseを使うのは呼出側で対象ファイルシステムの比較規則が確認できた場合だけとし、OS名だけで無条件に決めない。現時点の先行実装は比較規則不明として完全一致を使い、Workspace接続時の規則確定をP3-01に残す。

## 8. テスト

| ID | 正常系 | 異常系・境界値 |
| --- | --- | --- |
| FT-01 | 通常パス・明示リンク・相対指定 | 空、不正、大小文字別ファイル、循環、リンク先差替、特殊ファイル |
| FT-02 | UTF-8、CP932、UTF-16/32とBOM | 空、BOMのみ、矛盾する指定、不正末尾、曖昧な日本語、バイナリ |
| FT-03 | チャンクをまたぐデコード・CRLF | 1バイトずつ読む、サロゲート・最終CR、検証後の更新・消失 |
| FT-04 | 遅延展開、除外、名前順 | 空、権限不足、10,000件直下、折りたたみ中の完了、キャッシュ上限±1 |
| FT-05 | 深さ優先の検索列挙 | 深い階層、枝の失敗、リンク循環、取消時の全列挙器解放 |
