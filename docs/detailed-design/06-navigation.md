# 06 定義ジャンプ・参照探索

[索引](README.md) / 関連：[読取](03-files-tree.md)、[検索](05-search.md)、[本文移動](04-documents-tabs.md) / 上位：要件6章、基本設計6.4・6.5

## 1. 探索契約

`ISymbolNavigator`はNavigationに置く内部契約とし、画面は具体解析に依存しない。今回の実装は`SimpleSymbolNavigator`だけとする。

| 操作・型 | 入出力 |
| --- | --- |
| `FindDefinitions(request, ct)` | 固定ルート・除外・文字コード、識別子、操作識別を受け、宣言候補と終了情報を配信する |
| `FindReferences(request, ct)` | 同じ情報を受け、大小区別の単語一致で参照箇所を配信する |
| `WorkspaceSearchRequest` | 比較用の名前、ワークスペース条件、RequestId・WorkspaceEpoch・SearchEpoch。識別子の抽出元となる本文は保持しない |
| `WorkspaceSearchSession` | 有界の `SearchEvent<SearchHit>`、進捗、終了情報。定義は候補の種別名を抜粋に含める |

`SimpleSymbolNavigator` は既存の検索イベントを共用し、候補の原文位置・抜粋を返す。ファイル確定・無効化・終了は05の規則に従う。Operationsは検索枠を得た時点で対応する入口を呼び、候補数と全件評価の状態を見て自動移動を判断する。本文を開く責務は移動処理が持つ。

## 2. 識別子の抽出

1. 選択がある場合、改行・空白・複数トークンを含まず1識別子であることを確認する。
2. 未選択ならカーソル位置のスカラー値を調べる。区切り直後では直前が識別子の末尾ならその語を採る。どちらにも属さなければ有効識別子なしとする。
3. Unicode文字・数字・結合文字等の構成規則は通常検索と共有し、先頭の数字を許可しない。C#の`@name`は元の選択範囲に`@`を含め、比較用からだけ除く。
4. C#予約語をそのまま指定した場合は識別子でないとして通知する。`@class`等は識別子として扱う。コンテキストキーワードは宣言位置で判断し、抽出だけで一律に拒否しない。
5. C#以外の定義は非対応を通知する。参照は有効な単語なら同じ名前照合を利用できる。

Unicode正規化や名前空間・ジェネリック引数の付加はしない。`obj.Method`全体の選択は拒否し、Method単体の選択を案内する。Unicodeエスケープで記述した識別子は初期版の保証対象外とし、通常表記と黙って同一視しない。

### 2.1 識別子抽出の実装（2026-11-07）

設計済みNavigation内の`IdentifierExtractor`で、供給された原文Spanから名前と元の範囲を得る。本文/UI型を参照せず、通常検索のRuneカテゴリを再利用する。先頭はUnicodeのLetter/LetterNumberまたは`_`、以降は通常検索の単語要素とする。最大4,096 UTF-16単位（`@`を除く）で、超過・不正範囲・サロゲート途中・空・複数語・エスケープ表記を拒否する。選択があればCaretより優先し、未選択では語の途中/直後/`@`上を扱う。C#予約語は`@`付きのみ許可し、文脈キーワードは抽出で拒否しない。正規化/大小文字変換は行わない。

NV-01の正常/異常/Unicode/上限を35単体ケースで確認。実装は既存設計の内部責務で、外部公開API・層・依存方向・本文データ構造を変更しない。明示要求時だけ有界走査し、起動/描画/常駐索引を追加しない。UI側の原文取得と参照検索の接続はP5-06で行う。定義解析・探索契約全体とG4/G5は未完了。

## 3. 簡易字句走査

対象は除外後の通常の`.cs`ファイルだけとし、厳格にデコードした文字チャンクから逐次トークンを得る。改行は位置に反映し、宣言の途中の改行は区切りにしない。全文AST・参照解決・プロジェクト索引を作らない。

| 状態 | 処理 |
| --- | --- |
| `Code` | 識別子・キーワード・記号・数値を読む。コメント・リテラル開始を判定 |
| `LineComment` | 改行まで候補判定から除外 |
| `BlockComment` | 終端まで除外し、終端未完なら解析未完了 |
| `String / Char` | バックスラッシュエスケープを含め終端まで除外 |
| `VerbatimString` | 二重引用符によるエスケープを扱って除外 |
| `RawString / InterpolatedString` | 終端規則を確認できる対応パターンだけ除外。安全に終端を認識できない場合は解析非対応として当該ファイルを未評価にする |

リテラル中の`class Foo`等をコードとして検出しない。補間文字列やraw文字列は単純に次の引用符まで読み飛ばす実装にしない。対応パターンと未対応の組合せはPhase 5の固定データで示す。不完全構文・非対応構文で文脈を復元できない場合は、誤った候補を確定せず当該ファイルを無効化する。

`#if`等の条件は評価せず両分岐を読むため、同名候補・非コンパイル対象の候補が含まれ得る。プリプロセッサー行を候補としては扱わない。字句処理の位置は元本文に対応し、コメント削除後の文字列上のオフセットを返さない。

保持は現在トークン、宣言用の有界な直前トークン列、括弧・型本体の文脈スタック、対象名と少量の抜粋に限定する。解析上限は[共通予算](01-contracts.md)のLexerTokenChars・DeclarationTokens・DeclarationChars・LexerDepthを参照する。超過は未評価として通知し、巨大な宣言を黙って欠落させない。Phase 5前に解析予算として固定する。

### 3.1 逐次字句走査の実装（2026-11-07）

Navigationの`CSharpLexer`は任意分割のUTF-16を受け、識別子/キーワードの原文、概略数値、単一記号、本文を保持しないリテラルトークンを返す。位置は共通TextCursorによる64bit原文Offsetと1始まり行/UTF-16列。CRLFとサロゲートをチャンク途中で切っても位置を保つ。C#のNEL/LS/PSは字句上の改行として扱い、位置表示は既存本文のCR/LF契約に従う。条件付きコンパイルの式は評価せず、指令行以外の両分岐を走査する。

通常文字列/文字、逐語文字列、単行/複数行raw、通常/逐語/raw補間を処理する。補間の入れ子・式内の括弧/コメント/リテラルを追跡し、内容は宣言トークンへ出さない。rawは引用符数、複数行終端位置、`$`に応じた波括弧数を確認する。単純な書式部は除外し、書式部に引用符・開き波括弧・改行がある未対応形、Unicodeエスケープ識別子、未完了リテラル、不正UTF-16、上限超過は明示的なエラーとする。C#コンパイラー相当の数値/構文検証やrawインデント値の生成は行わない。

先読み16 Ki + 4単位、語/数値4,096単位（`@`のみ1単位追加）、raw開始区切りの引用符/`$`各4,096、リテラルと補間内括弧の合計深さ1,024を上限とする。長いコメント/リテラル本体を保持しない。`Push`中のトークンは仮で、`Complete`成功時だけファイルを確定できる。取消/消費側停止/例外時は作業領域をクリアし、終了後だけ再利用できる。

`CSharpFileLexer`は既存FileReaderから厳格復号済みチャンクを借り、`.cs`に限定する。Stamp確認後にEOFを確定し、読取/解析の失敗・停止時は`CanCommit=false`を返して当該ファイルの候補を無効化できる。借用したPreparedTextの所有は呼出元のまま。宣言側の予算と確定判定は4.1節、候補配信と画面接続は5.1節に記載する。定義探索を要求したときだけC#走査を行う。

[76件の単体・実ファイル検証と補助スモーク](../validation-results/2026-11-07-csharp-lexer/README.md)。境界の仕様参照：[C#字句構造](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/language-specification/lexical-structure)、[raw文字列](https://github.com/dotnet/csharplang/blob/main/proposals/csharp-11.0/raw-string-literal.md)、[補間文字列](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/tokens/interpolated)。

## 4. 宣言候補の検出

| 種別 | 初期対応の形 | 判定に使う文脈 |
| --- | --- | --- |
| 型 | `class N`、`struct N`、`interface N`、`enum N`、`record N`、`record class/struct N` | 名前トークンの完全一致。型の入れ子も文脈スタックで扱う |
| Delegate | `delegate ReturnType N(...)` | 戻り値の後の名前・引数列・終端 |
| Method | `ReturnType N(...) { ... }`、`=> ...;`、インターフェース等の`;`宣言 | 型本体直下。修飾子・属性・ジェネリック引数・制約を有界窓で読む |
| Property | `Type N { get; ... }`、`Type N => ...;` | 型本体直下で引数列のないメンバー形 |
| Field | `Type N;`、`Type N = ...;`、`Type A, N;` | 型本体直下。初期化式の括弧・波括弧で区切りを誤認しない |

メソッド・プロパティ・フィールドは、メソッド本体等の内部にいる場合は候補にしない。呼出し`obj.N()`やローカル変数は宣言扱いにしない。対象名の一部だけの一致は除外する。

コンストラクター、演算子、インデクサー、明示的インターフェース実装、ローカル関数、複雑な関数ポインター・新構文等は初期対応一覧に含めず、既知の精度制限として記録する。単純なメソッド・型の受け入れ要件は固定データで必ず確認する。構文の追加で全文ASTに拡大しない。

条件付きコンパイルのディレクティブ行は読み飛ばす。プロジェクトごとのシンボルは評価しないため、`#if false` 内や非アクティブな分岐の宣言も候補になることがある。

候補の位置は名前の開始。重複は同ファイル・同オフセット・同種別に限りまとめ、同名の別宣言は残す。候補確定のために必要なトークンの終端を待ってから返す。解析未完了で仮候補を返していた場合はFileInvalidatedで取り消す。

### 4.1 宣言候補検出の実装

`CSharpDeclarationScanner`は厳格復号済みの字句を順に受け取り、対象名と大小文字まで一致する宣言の種別と原文範囲を返す。`@N`は比較時に`N`として扱い、返す範囲には`@`を含める。同名の型やオーバーロードは位置ごとに残す。

名前空間と型の直下を追跡し、メソッド本体などのブロックは括弧の対応を確認して読み飛ばす。フィールドは初期化式内の括弧や型引数を考慮して宣言子を分ける。属性、改行、ジェネリック、基本的な制約、式形式のメソッドとプロパティ、アクセサーと初期化子のあるプロパティを固定試験に含めた。

宣言ヘッダーと初期化式の作業範囲は終端を含めて256トークン・16 Ki UTF-16単位、スコープと括弧は合計1,024階層まで保持する。上限超過や括弧の不整合、未完了の宣言ではそのファイルを確定しない。候補は字句読取と宣言走査の両方が完了するまで仮扱いとする。式と制約の型解決、C#構文全体の妥当性検証は実装範囲外。

通常画面への接続は5.1節に記載する。固定試験は正常系、呼出し・ローカル変数の除外、同名、原文範囲、上限、実ファイルの確定・無効化を含む47件。macOSの通常テストは.NET 938件とPython 112件が成功した。

## 5. 完了と候補選択

| 状態 | 表示・操作 |
| --- | --- |
| 全件評価済み、候補1件 | その候補へ移動する |
| 全件評価済み、候補複数 | 「名前一致による宣言候補」の共用一覧を表示 |
| 全件評価済み、0件 | 「定義が見つかりません」 |
| 取消・上限・読取/解析の未評価あり | 部分結果を表示。1件でも自動移動しない。確定済み候補の明示選択は可能 |
| ルートや識別子なし | 実行せず必要条件を案内 |

「定義へジャンプ（簡易）」はコンパイラレベルの精度を保証せず、同名、オーバーロード、名前空間、継承、型推論は解決しない。未評価を含む0件は「見つからなかったが未評価あり」と表示し、完全な未検出と区別する。

### 5.1 候補一覧と移動の実装

F12と検索メニューから、選択またはCaretの識別子を抽出する。検索対象は現在のワークスペース内で除外・リンク規則を通過したC#ファイル。比較は大小文字を区別した名前一致で、候補一覧に宣言名と種別、原文位置を表示する。

簡易探索は既存の検索ワーカーへファイルごとの宣言走査を渡す。候補を原文の名前範囲と宣言種別の表示を持つ共用結果へ変換し、既存の有界バッチ、確定、無効化、取消、操作世代を使う。読取や解析に失敗したファイルは未評価とし、同ファイルの仮候補を無効化する。移動時は共用の原文位置とファイルStampの検証を行う。

全件評価済みで確定候補が1件かつ操作世代・表示・入力世代が一致するときだけ自動移動する。複数候補、取消、上限、未評価ありでは確定候補から明示的に移動できる。0件では未評価の有無を表示する。通常テストに単独候補の原文選択、複数・部分結果の明示選択、0件、取消・後続入力、10,000件上限を追加した。実GUIプローブはF12、メニュー、Enterの経路を検証する。

## 6. 参照検索

SimpleSymbolNavigatorはIdentifierQueryの名前を、`MatchCase=true`、`WholeWord=true`、`UseRegex=false`の検索要求へ変換する。検索語の正規表現エスケープは不要で、正規表現そのものとして実行しない。

対象はルート内の全テキストファイル。宣言・コメント・文字列も含める。`@name`はnameで照合し、単語境界により`othername`等は除外する。一致位置は元本文のnameに対応し、必要に応じて補助表示で`@`も見せる。意味的な同一シンボルの参照であるとは表示しない。

### 6.1 参照検索UIの接続（2026-11-07）

通常の本文表示でShift+F12、または「検索 → 参照を検索（名前一致）」を使う。選択優先・未選択はCaretの識別子を採り、C#では`@`を比較名から除く。選択なし/不正語/フォルダなしは案内を表示し、既存の検索結果を破棄しない。抽出は現在の文書から最大8,196 UTF-16単位の窓だけを取り、境界に達した語や4,096単位超の語を短い語に切り替えない。

初期の参照入口は既存SearchPanel/Coordinatorへ同じ検索要求を渡す。MatchCase=true、WholeWord=true、UseRegex=falseを固定して開始し、共用の単一ワーカー・結果上限・取消・世代・確定/未確定と結果移動を再利用する。結果パネルには「名前一致」「宣言・コメント・文字列も含む」「意味解析は行わない」を表示する。通常検索を実行した際は通常の説明へ戻す。

UTF-8/CP932・日本語/補助平面/結合文字、条件の上書き、予約語の`@`表記、長い本文中の上限境界、原文位置への結果移動と本文不変を単体/結合で確認する。専用GUI試験は実コントロールのrouted Shift+F12、メニューClick、結果Enter、バインドされた説明・選択・フォーカスを確認する。物理キー/IME・包括的な性能受入とは区別する。

[両OSの実GUI検証](../validation-results/2026-11-07-reference-search/README.md)は各3プロセス・39検証すべて成功。対象単体/結合49件と両OS通常試験も成功した。

これは設計済みの参照機能の接続で、新しい層/プロジェクト・外部公開API・本文/タブ/ファイル形式を導入しない。定義と参照は内部のISymbolNavigatorに接続済み。索引/AST/ファイル一覧の常駐を追加せず、参照検索要求時以外は抽出を行わない。ワーカー性能は既存通常検索と同じ評価対象で、正式な大規模性能測定はP4/P5-07へ残す。有界表示の専用試作では表示位置を原文と誤認しないよう入口を拒否し、通常UIだけに接続している。

メソッドのGUI受け入れでは、呼び出し位置から宣言へ移動し、コメント・文字列に書かれた疑似宣言を除外した。参照検索は同じ名前の宣言・呼び出し・コメント・文字列を返した。未完のC#ファイルが検索範囲にあるときは部分結果を表示し、候補が1件でも自動移動を保留した。[両OSのGUI検証](https://github.com/m-hiroaki/codeView/actions/runs/43422579665)

class、struct、interface、enum、record、delegate、プロパティ、複数宣言子の後続フィールドでも、F12で別ファイルの宣言へ移動し、原文の宣言名を選択して本文へフォーカスすることを確認した。候補が0件なら案内を表示し、元ファイルとカーソル位置を保つ。[Windows/macOSのGUI各3回](https://github.com/m-hiroaki/codeView/actions/runs/43430037124)

## 7. テスト

| ID | 正常系 | 異常系・境界値 |
| --- | --- | --- |
| NV-01 | 選択・カーソル・`@name`・Unicode識別子 | 空、数字先頭、予約語、複数語、ドット列、語直後、エスケープ表記 |
| NV-02 | 型・delegate・method・property・field | コメント・文字列内の偽宣言、呼出し、ローカル、構文不完、宣言上限 |

固定データには期待候補と既知の誤検出・見逃しを分けて記録する。単一の百分率だけでVisual Studio相当の精度を示さない。対応構文・制限は実装と同時に更新する。
