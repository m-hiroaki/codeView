# 07 設定・配布

[索引](README.md) / 関連：[起動](02-runtime-ui.md)、[ファイル](03-files-tree.md) / 上位：基本設計9章、アーキテクチャ設計4・5.4・9章

## 1. SettingsStoreの契約

| 操作 | 入出力・失敗 |
| --- | --- |
| `LoadAsync(ct)` | 保存場所を内部で決め、検証済みSettingsSnapshotまたは既定値と警告を返す |
| `Validate(json)` | 大きさ・版・型・値を検証。不正な設定を操作へ渡さない |
| `SaveAsync(snapshot, ct)` | 決まった専用パスだけへ保存し、成功・失敗を返す。ソースパス引数は持たない |

設定スナップショットは形式版と除外名リストだけを持つ。テーマ・履歴・本文・最近の検索語・レイアウトを初期JSONへ追加しない。UIからの設定操作を増やさず、当面はJSONを変更して再起動で適用する案とする。

## 2. JSONスキーマ

```json
{
  "schemaVersion": 1,
  "excludedDirectoryNames": [".git", "bin", "obj", "node_modules"]
}
```

| 項目 | 検証・既定値 |
| --- | --- |
| JSON全体 | UTF-8、オブジェクト、最大64 KiB。破損・超過は既定値と警告 |
| schemaVersion | 整数1。省略は1として補完。未知版は黙って上書きせず読込警告・保存禁止 |
| excludedDirectoryNames | 文字列配列。省略は既定の4名、空配列は除外なし |
| 除外名 | 空・`.`・`..`・パス区切り・NUL・改行・glob記号を拒否。相対パスではなく単一の名前 |
| 件数と長さ | 初期上限256名、各255 Unicodeスカラー値。超過・不正値は設定全体を既定へ戻して通知 |
| 重複 | 元の文字列の完全一致を除去。対象OSの照合規則はExclusionPolicyで適用 |
| 未知項目 | 利用せず保持上限内で無視。将来の保存で消さないため、未知項目ありのファイルの自動再保存はしない |

自動補完した設定を起動時に無条件で保存しない。誤ってユーザーのファイルを修復・消去したことにしない。表示用のJSONエラーは行・項目名程度とし、内容全文を通知・永続ログへ出さない。

UTF-8 BOMは除いて検証する。同名JSONプロパティの重複は値の解釈を曖昧にしないため不正として扱う。未知項目がある場合は読込を許すが保存許可を返さない。初期実装では設定のリンク・ディレクトリ・デバイスも不正とし、ポータブル設定の失敗をユーザー設定への暗黙フォールバックに変えない。

## 3. 保存場所と優先順位

1. Windowsは実行ファイルの隣、macOSは`.app`の外側の隣にある`codeview.settings.json`を調べる。
2. そのパスが存在する場合はポータブル設定として選ぶ。読めない・不正な場合も他の設定へ黙って切替えず、既定値と警告で継続する。
3. 存在しなければ、WindowsはユーザーのLocalApplicationData下のcodeView、macOSはユーザーLibrary/Application Support/codeViewを候補にする。OSの推奨APIで解決し、固定ユーザー名を使わない。
4. ユーザー設定もなければ既定値を使い、明示的な保存時だけディレクトリとJSONを作る。

`.app`内部やレジストリへ書き込まず、起動場所が書込不可でも閲覧可能にする。書込先を任意のコマンドラインパラメーターや閲覧対象パスから生成しない。

## 4. 保存時の安全性

保存は専用設定の明示変更がある場合だけ行い、通常終了や例外時の自動保存は行わない。D-07の解釈確認が済むまで製品の保存機能は有効にしない。保存失敗は閲覧の失敗としない。

- 対象がシンボリックリンク・特殊ファイルなら保存しない。存在するハードリンクの判別可能性も両OSで確認し、判別できない危険な置換は許可しない。
- 閲覧中のソースと同一の設定パスへ保存しない。AppOperationsが管理する開いたパスとの衝突も確認する。同一性確認は完全な競合防止サンドボックスとは扱わない。
- 同じ専用ディレクトリにアプリ固有の一時名を排他的に作り、UTF-8で書き、完了後に置換する。任意のソースへ一時ファイルを作らない。
- 読込後に設定ファイルが変わっていた場合は競合を通知して停止し、他の変更を黙って上書きしない。元ファイルを消してから書く方式は使わない。
- 一時ファイル作成・書込・置換が失敗したら可能な範囲で一時物を削除し、旧設定を維持する。別ボリュームへのフォールバックやOS権限の昇格を行わない。

## 5. SDK・依存関係の固定

採用する.NET最新LTSとAvalonia・AvaloniaEdit・TextMate連携・CP932対応をPhase 1〜2で確認する。確認時点の具体版をSDK設定・プロジェクト・依存ロックへ記録し、ビルドごとの暗黙更新を避ける。ここでは未調査の版番号を確定しない。

製品は`src/codeView`、試験は`tests/codeView.Tests`の2プロジェクトを初期構成とする。追加ツール・テスト基盤の採用は必要性を示し、製品起動経路にテスト・計測依存を混ぜない。文法・テーマ・ライセンスを成果物へ同梱し、初回起動時のネット取得をしない。

## 6. 発行候補と確認

| 対象 | 初期候補 | まだ決定しない事項 |
| --- | --- | --- |
| Windows | 自己完結型のexeを含むコピー可能な構成 | x64 / Arm64の提供範囲、単一ファイル、署名 |
| macOS | 自己完結型の`.app`をコピーして起動 | Arm64 / x64、署名・公証、配布アーカイブ |
| 両OS | 文法・必要なネイティブ依存・ライセンスを同梱 | ReadyToRunの効果、発行サイズ・実行時展開の影響 |

単一ファイルと最小フォルダ構成をReleaseで比較し、起動・展開・本文表示・文字コード・メモリを測る。Native AOT・トリミングは採用前提にしない。製品機能として外部プロセス・検索ツール・開発SDKに依存しない。

発行記録にはRID、SDK・依存版、ビルド設定、発行形式、成果物のハッシュ、同梱物とライセンス、署名状態を含める。正確なコマンドとパッケージ構成はD-01・D-08で決定して記録する。

## 7. OS別受け入れとオフライン

開発SDKも追加ランタイムもない別環境でコピー起動する。macOSはFinderから初回起動・パスのドロップ・IME・ファンクションキー・Retina・トラックパッドを確認する。配布経路の隔離属性とGatekeeperを有効にしたまま、決めた手順で起動できるか検証する。

署名確認を含む初回と通常起動を別測定し、オフライン初回起動の制約も確認する。署名なしで警告が出ないとは保証しない。通信不可の環境でも本文・構文色・検索が利用でき、文法・テレメトリ・自動更新に接続しないことを確認する。
