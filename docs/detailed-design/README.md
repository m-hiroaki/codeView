## 2. 上位設計との関係

単一プロセス、製品1プロジェクトと試験1プロジェクト、小規模MVVM、読取と設定書込の分離、索引なし、逐次走査、上限付き結果、タブによる本文所有を維持する。本書の型名とメソッドは内部実装の設計であり、外部公開APIではない。SDK・ライブラリの確定前に、特定バージョンのAPIが利用可能とは扱わない。

Operationsの将来のCoordinator分割やDocumentNavigatorの分離は実施しない。既存の論理領域内の状態・メソッドを具体化する。汎用DI、イベントバス、Domain層、独自仮想本文モデルを追加しない。アーキテクチャに影響する変更は上位設計の承認手順に従う。

メソッドの記法は設計用のC#風表記である。非同期メソッドは`Async`、取消引数は`ct`、業務上想定する失敗は構造化結果、未知の例外は例外境界へ渡す。完全なコンパイル可能コードや採用ライブラリのAPI宣言ではない。

## 3. 実装上の不変条件

1. ソースを変更せず、本文保存契約を持たない。書込は専用設定に限定する設計案を引き継ぐ。
2. I/O・走査・照合をUIスレッドで実行しない。状態の採用はUI側の短い直列処理で行う。
3. 設定が確定する前にOpen・列挙・検索を開始しない。
4. 非同期結果は所有者・世代・文書版が有効な場合だけ採用する。
5. 結果キュー・処理要求・抜粋・一致位置・エラー代表例は上限を持つ。
6. キュー、Task、ストリーム、文書、読取ビューの解放責任を一意にする。
7. 古い処理の完了待ちでUIを止めず、古い処理が停止する前に無制限に代替ワーカーを起動しない。
8. 検索結果の完了・部分結果・上限・取消を区別する。文法失敗はプレーン表示で閲覧を継続する。
9. Unicode正規化を行わず、元本文に対応する位置を扱う。
10. 起動・応答・メモリを検索完了速度より優先する。

## 4. 具体化した値と検証待ちの区別

上位の1秒起動、UI応答100ms等は上位設計の目標として維持する。キュー容量や待機時間等の数値は[共通規約](01-contracts.md)の初期候補とし、試作前に試験設定へ固定する。測定で変更した場合は理由・結果・文書を同時更新する。本文メモリ・検索速度の予算は、未測定の推測値で確定しない。

| ID | 検証待ち・確認事項 | 実施時期・完了条件 |
| --- | --- | --- |
| D-01 | SDK・Avalonia・本文・文法の採用版 | Phase 1〜2。互換性を確認し、SDKと依存版・ライセンスを固定 |
| D-02 | DocumentAdapterの構築スレッド、読取ビュー、全文保持量 | Phase 2。50 MiB・100 MiB・複数タブ、UI接続・解放の実測で採否判断 |
| D-03 | 色分け停止閾値、本文メモリ・読込時間・GC予算 | Phase 2開始前に予算固定、終了前に測定・合否。未決なら表示方式を確定しない |
| D-04 | ファイル内検索の採用方式、保持上限・反応時間 | Phase 2で実現性、Phase 4で段階的・可視優先・必要時探索を比較 |
| D-05 | 検索時間・メモリ・GC予算とCold / Warm準備 | Phase 4開始前。基準機とL1の条件別予算・手順を固定 |
| D-06 | 厳格な文字コード事前検証の追加I/O | Phase 2・4。03の複数パス方式を測定。未達時は文字コードの正確性・部分結果仕様を含め再検討 |
| D-07 | 設定保存と書込禁止の解釈 | Phase 1。専用設定の書込のみを例外として許す案を確認。未確認でもソース書込を追加しない |
| D-08 | 署名・公証、CPU、発行形式 | Phase 6前。別PCとオフラインの初回起動で判定 |
| D-09 | 規模別・長時間試験の予算 | L1は必須評価、L2は拡張、L3は限界調査。8時間・各1,000回の資源許容幅を試験前に固定 |
| D-10 | 検索の行単位・正規表現制限・補助平面文字 | Phase 4前に詳細仕様を確認。05の制約と境界試験を実施 |
