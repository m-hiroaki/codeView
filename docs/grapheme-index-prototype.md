# 文字素境界索引の独立試作

2026-11-06。[承認済み設計](unicode-context-proposal.md)の最初の部品。`DocumentGraphemeIndex`はまだBuilder・Handle・表示セッション・GUIへ接続していない。通常の読込・起動・検索・描画では呼び出されず、追加走査や保持はない。

## 実装範囲

- 不変のReadLeaseを明示的に渡して構築する。約4 Ki UTF-16間隔で、StringInfoが確定した文字素境界だけを保存する。大きな本文では保持予算に合わせて間隔を広げる。
- 本文全体を複製しない。作業窓は64 Ki UTF-16、原文読取は既存の16 Ki単位。索引配列と管理情報の保守的な見積りを合わせて1 MiB以下に制限する。
- 窓末尾の最後の文字素は、EOF以外では確定しない。サロゲートの途中を再開位置にしない。確定境界から再開し、長いprefixを照会のたびに全走査しない。
- 照会も一つの作業窓まで。確定できなければfalseを返す。単一文字素が窓を超えると構築を止め、`IndexedLength`と`IsComplete=false`で未解決のsuffixを明示する。未解決位置の境界を推定しない。
- 原文を変更せず、取消を読取/文字素ごとに確認する。索引は構築元Leaseへの弱参照だけを持ち、本文やLeaseの寿命を延ばさない。今回の部品は同じ生存中のLeaseだけで照会でき、別Leaseや破棄済みLeaseは拒否する。

## 検証と限界

13単体ケースで全文StringInfoとの照合、ASCII/日本語/CRLF/結合文字/ZWJ/RI/Jamo/Indic/Prepend/不正サロゲート、4 Ki付近・64 Kiの窓境界、上限前後の巨大結合列、取消済み要求、範囲外、別Lease、本文閉鎖後の既存LeaseとLease破棄を確認する。複合入力では読込チャンクを701単位に分割し、再開後の照会を全文の境界と照合する。

これは実行環境のStringInfoを対照にした初期検証であり、固定版Unicode公式適合データによる適合証明ではない。構築中の取消遅延、50/100 MiBの構築CPU/メモリ・照会量の両OS比較、GC/回収確認は後続。保持量は配列容量と管理情報の見積りであり、プロセスメモリ実測とは区別する。作業窓のArrayPool/読取用一時領域は索引保持とは別に存在する。

次は公式データ/再開の追加検証、性能計測、同じ本文世代の複数Leaseで共有できるワーカー/Handle接続を進める。Arabic連結・Bidi段落の配置文脈と専用Controlは未実装で、既存の8件の視覚未達、A-04-03-04とG2は未完了を維持する。
