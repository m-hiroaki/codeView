# 文字素境界索引の独立試作

比較画面では、ドラッグ開始行がポインターを捕捉し、行をまたぐと移動先の配置へ座標を変換する。4行を2行分の表示領域に置いた検証では、ポインターを上下の外に置いている間にタイマーで1行ずつ表示を移し、原文の選択を広げる。表示範囲へ戻るとスクロールを止めて行内の選択を続ける。ボタン解放や捕捉喪失でタイマーを止め、コピーには元のCRLFを含める。[両OSのGUI検証](https://github.com/m-hiroaki/codeView/actions/runs/43444171212)比較画面以外の行別表示試作と物理入力は後続で扱う。

固定12ケースで、可視部分の全文字素境界について、先頭境界を基準にした横位置を全文AvaloniaEditの位置と比較した。macOSとWindowsの各3プロセスで11ケースは差0.1 DIP以内だった。タブ・日本語・絵文字・ヘブライ文字・アラビア文字を同時に含む `unicode-full-control` は、両OSの全回で差が残った。画像の画素一致と物理入力はこの測定の対象外。[比較結果](https://github.com/m-hiroaki/codeView/actions/runs/43439885493)

再比較では、全文表示と同じタブ幅と段落終端をAvaloniaに渡した。途中の測定で残っていた差は、右から左の文字で終わる行の末尾（UTF-16位置28）に限られた。段落終端を揃えた後は、両OSの各3プロセスで固定12ケースすべての位置差が0.1 DIP以内になった。[再比較結果](https://github.com/m-hiroaki/codeView/actions/runs/43441227930) [AvaloniaEditの行末処理](https://github.com/AvaloniaUI/AvaloniaEdit/blob/86fdebec4cff7affb0e14c7885df71d28edce777/src/AvaloniaEdit/Rendering/VisualLineTextSource.cs)

比較画面では、配置エンジンのヒット位置が文字素の途中なら、前後の境界のうち同じ配置上でポインターに近い方へ移動する。固定ケースの可視範囲で、選択位置が原文の文字素境界にあることを確認した。最初の文字素が行の通常の幅に収まらない場合は、後続行の通常枠と区切りを確保したうえで、投影全体の残り予算からその文字素を丸ごと表示する。残り予算にも収まらない場合は入力位置を提供しない。

[承認済み設計](unicode-context-proposal.md)の文字素境界索引。`DocumentGraphemeIndex`は任意のBuilder収集、Handleでの保持、表示セッションからの照会まで接続した。専用の診断ビルドで `CODEVIEW_GUI_ROWS=1` と `CODEVIEW_GUI_GRAPHEME_INDEX=1` の両方を指定すると、読込ワーカーで収集する。既定では収集しない。

## 実装範囲

- 不変のReadLeaseを明示的に渡して構築する。約4 Ki UTF-16間隔で、確定した文字素境界だけを保存する。大きな本文では保持予算に合わせて間隔を広げる。
- 本文全体を複製しない。作業窓は最大64 Ki UTF-16、原文読取は既存の16 Ki単位。境界照会は要求位置までの距離に128単位を足した範囲から始め、境界が確定しない場合だけ窓を広げる。索引配列と管理情報の保守的な見積りを合わせて1 MiB以下に制限する。
- 窓末尾の最後の文字素は、EOF以外では確定しない。サロゲートの途中を再開位置にしない。確定境界から再開し、長いprefixを照会のたびに全走査しない。
- 照会も一つの作業窓まで。確定できなければfalseを返す。単一文字素が窓を超えると構築を止め、`IndexedLength`と`IsComplete=false`で未解決のsuffixを明示する。未解決位置の境界を推定しない。
- 原文を変更せず、取消を読取/文字素ごとに確認する。索引はAvaloniaEditの本文世代への弱参照を持つ。同じ本文世代の生存中のLeaseから照会でき、別文書・別世代・破棄済みLeaseを拒否する。世代情報を持たない入力は構築元のLeaseと照合する。Handleを閉じると索引への参照を解放する。

## 検証と限界

13単体ケースで全文StringInfoとの照合、ASCII/日本語/CRLF/結合文字/ZWJ/RI/Jamo/Indic/Prepend/不正サロゲート、4 Ki付近・64 Kiの窓境界、上限前後の巨大結合列、取消済み要求、範囲外、別Lease、本文閉鎖後の既存LeaseとLease破棄を確認する。複合入力では読込チャンクを701単位に分割し、再開後の照会を全文の境界と照合する。

構築中の取消遅延、50/100 MiBの構築CPU/メモリ・照会量の両OS比較、GC/回収確認は後続。保持量は配列容量と管理情報の見積りであり、プロセスメモリ実測とは区別する。作業窓のArrayPool/読取用一時領域は索引保持とは別に存在する。

[Unicode 16.0.0の公式データ](https://www.unicode.org/Public/16.0.0/ucd/auxiliary/GraphemeBreakTest.txt)は、[.NET 10のデータ版](https://github.com/dotnet/runtime/blob/v10.0.0/src/libraries/System.Private.CoreLib/Tools/GenUnicodeProp/GenUnicodeProp.csproj)に合わせてテスト専用に同梱する。SHA-256は `ee2b9354d270ac061b29f09662cafea06341d77e704b8cc6bd72aaeeda363cb5`。同梱のLICENSE.txtはUnicode License V3。

初回照合では、[.NET 10のStringInfoがGB9cを実装していない](https://github.com/dotnet/runtime/issues/111546)ため、公式1,093例中7例で差が出た。索引の分割にGB9cを補い、本文冒頭と4,096単位の索引再開点で全例のUTF-16位置を公式境界と照合する。64 Ki窓の継ぎ目では、ZWJで結合が続く場合とZWNJで切れる場合も確認する。

GB9cに使う3種類のIndic_Conjunct_Break範囲を[Unicode 16.0.0のDerivedCoreProperties.txt](https://www.unicode.org/Public/16.0.0/ucd/DerivedCoreProperties.txt)から取り、同じ値で隣接する範囲を統合する。原典のSHA-256は `39d35161f2954497f69e08bdb9e701493f476a3d30222de20028feda36c1dabd`。StringInfoの分割境界の直後が子音の場合に限り、直前に子音とリンカーの列があるかを確認する。試作の構文色の境界検査にも同じ分割を使う。

索引がある行別投影では、表示開始位置を手前の文字素境界へ戻し、その位置から既存の表示文字数予算内に収まる境界までを取得する。文字素が1つも収まらないか境界を確定できない行は、専用GUIの余白に交差印を出し、空の表示位置から原文への移動を拒否する。選択範囲のコピーには従来の原文を使う。

索引を使う行別投影は、表示部分と同じ論理行全体の原文範囲を描画用メタデータとして持つ。行全体を使うことで前後の字形や段落方向の情報を渡せる。文脈の取得枠は1投影につき合計64 Ki UTF-16単位とし、残り枠に収まらない行の文脈は取得不可とする。現在の投影の文脈だけを原文から必要時に読み出す。表示テキスト、原文位置変換、コピーは描画用文脈と独立して扱う。

専用GUIの視覚比較に、Avaloniaの `TextLayout` で原文の論理行を配置する行描画Controlを追加した。可視範囲の矩形ごとにクリップし、同じ配置のヒットテスト結果を原文のUTF-16位置に戻す。比較画面が一度に持つ配置は1行で、上限は16 Ki UTF-16単位。候補を切り替えるたびに旧配置を破棄する。[Avaloniaの配置実装](https://github.com/AvaloniaUI/Avalonia/blob/8eeda4f6f546165b3f72e63c9f42247abb306905/src/Avalonia.Base/Media/TextFormatting/TextLayout.cs)

比較画面では、原文のAnchor/Caretを受け取り、同じ配置から選択背景とCaretを描く。選択背景は可視範囲でクリップし、表示範囲外のCaretは描かない。クリック、Shiftクリック、ドラッグは、現行投影の文字素境界を通して既存の原文選択処理に渡す。

## 実ファイルの行別表示

文脈付きの行は、原文を解析した構文色を同じ行の文字配置に適用する。色の切り替えが文字素の途中に入る範囲は既定色で描画する。原文の大きさや行長に対する既存の構文解析上限は、試作でも適用する。

ファイル内検索は原文を走査し、「次へ」「前へ」で一致した原文範囲を選択する。一致範囲は表示中の行に切り詰めて描画する。文脈を取得した行では文字配置を、長すぎて文脈を取得できない行では行別投影の位置対応を使う。

定義ジャンプと参照検索はキャレットまたは選択の原文位置から識別子を取り出す。結果から別ファイルへ移動する場合も、そのファイルの原文位置を選択して表示する。

同じフラグを指定した行別表示の専用試作でも文脈付き描画を使う。既存のエディターがスクロール・入力捕捉を管理し、文脈を取得できる行では描画とポインター位置の変換に同じ配置を使う。ドラッグで行の描画範囲を外れたときは最も近い表示範囲に寄せる。選択とコピーは原文の位置に従う。

一度に配置する原文は全行の合計で最大16 Ki UTF-16単位。文脈を取得できない行やこの枠に収まらない行には従来の行別描画を使う。同じ原文行、フォント、構文色の配置は、画面上の表示範囲だけが変わった場合に再利用する。画面から外れた行や原文を切り替えたときは対応する配置を破棄する。通常画面への採用、物理入力、視覚列による横スクロールと両OSの性能評価は引き続き扱う。

索引がある場合、左右キーは原文の文字素境界へ移動する。Shiftを押しながら移動すると文字素全体が選択される。上下移動で目的の列が文字素の途中にある場合は、その文字素の先頭に寄せ、次の行へ移動するときの目標列は保持する。索引で境界を確定できない範囲は従来のスカラー単位で移動する。
