# 要件定義書 — 軽量ソースコードビューア　codeView

> AI（Claude Code 等）による開発の入力として使うことを想定した要件定義書です。
> 「【仮定】」と書かれた項目は、ヒアリングで明示的に決まっていないためこちらで補った内容です。違う場合は修正してください。

---

## 1. 概要

コードリーディングに特化した、軽量なソースコードビューア。
閲覧に必要な最小限の機能だけを持ち、起動の速さと大規模なコードベースでの快適さを最優先する。

### 1.1 目的

- ソースコードを「読む」作業を、重いIDEを立ち上げずに素早く行えるようにする
- コードの読解に直結する機能（ツリー、検索、ジャンプ）だけに絞り、操作と画面を単純に保つ

### 1.2 設計方針（優先順位順）

1. **起動が速い**（目標：1秒以内）
2. **巨大ファイル・大規模フォルダでも動作が重くならない**
3. **機能は必要最小限**（迷ったら入れない）
4. **インストール不要**（実行ファイルのコピーだけで動く）

## 2. 対象ユーザーと利用環境

| 項目           | 内容                                                      |
| -------------- | --------------------------------------------------------- |
| 利用者         | 開発者（主に自分用）                                      |
| 認証           | 不要                                                      |
| 対応OS         | Windows、macOS                                            |
| 主に読むコード | C# / .NET（ただしテキストファイルなら言語を問わず開ける） |
| 形態           | デスクトップアプリ                                        |
| ネットワーク   | 不要（完全オフラインで動作。外部通信を行わない）          |

## 3. 技術スタック

| 項目             | 選定                                                                    |
| ---------------- | ----------------------------------------------------------------------- |
| 言語・ランタイム | C# / .NET（最新LTS）                                                    |
| UIフレームワーク | Avalonia（クロスプラットフォームUI）                                    |
| テキスト表示     | AvaloniaEdit を第一候補（読み取り専用モードで使用、構文ハイライト対応） |
| 構文ハイライト   | TextMate文法ベース（AvaloniaEdit.TextMate 等）を第一候補                |

【仮定】上記のライブラリ選定は推奨案。起動速度や大容量ファイルでの性能要件を満たせない場合は、代替（自前の仮想化描画など）に変更してよい。

## 4. 機能要件

### 4.1 必須機能

| ID   | 機能           | 概要                                                                         |
| ---- | -------------- | ---------------------------------------------------------------------------- |
| F-01 | ファイルを開く | 単体ファイルを開ける                                                         |
| F-02 | フォルダを開く | フォルダを開き、子フォルダを含めてツリー表示する                             |
| F-03 | ファイルツリー | VS Code のエクスプローラーのように、フォルダの展開・折りたたみができる       |
| F-04 | 構文ハイライト | 拡張子から言語を判定して色分け表示する                                       |
| F-05 | 全文検索       | 開いているフォルダ内を横断検索（grep的）。結果一覧から該当行へジャンプできる |
| F-06 | 定義ジャンプ   | カーソル位置（または選択）の識別子の定義へ移動する（簡易版、6章参照）        |
| F-07 | 参照検索       | 識別子が使われている箇所を一覧表示し、選択でジャンプする（簡易版、6章参照）  |
| F-08 | タブ           | 複数のファイルをタブで同時に開ける                                           |
| F-09 | ファイル内検索 | Ctrl+F（macOSは Cmd+F）で開いているファイル内を検索・ハイライトする          |

### 4.2 各機能の補足

**F-01 / F-02 ファイル・フォルダを開く**
- 開く方法：メニュー、ドラッグ&ドロップ、コマンドライン引数
- 拡張子を問わず、テキストファイルなら開ける
- バイナリファイルを開こうとした場合は、開かずに「バイナリのため表示できません」と通知する

**F-03 ファイルツリー**
- ツリーは遅延読み込み（展開したフォルダの中身だけを読む）にし、大規模フォルダでも初期表示を速くする
- 【仮定】`.git`、`bin`、`obj`、`node_modules` はデフォルトでツリーと検索の対象から除外する（設定で変更可能）

**F-05 全文検索**
- 検索オプション：大文字小文字の区別、単語単位、正規表現
- 検索は別スレッドで実行し、UIをブロックしない。結果は逐次表示し、検索のキャンセルができる
- バイナリファイルと除外フォルダは検索対象外

**F-08 タブ**
- タブの閉じる操作、切り替え（Ctrl+Tab 等）に対応
- ツリーでファイルを選ぶと、既に開いていればそのタブをアクティブにする

### 4.3 やらないこと（スコープ外）

- ファイルの編集・保存（**完全な読み取り専用**）
- アウトライン（シンボル一覧）表示
- ブックマーク・メモ
- テーマ切り替え（【仮定】ダークテーマ1種類、またはOS設定追従のみ。切り替えUIは作らない）
- デバッグ、ビルド、Git操作、拡張機能（プラグイン）
- Linux 対応（将来の拡張としては可）

## 5. 非機能要件

### 5.1 性能

| 項目           | 要件                                                                                         |
| -------------- | -------------------------------------------------------------------------------------------- |
| 起動時間       | 1秒以内を目標（アプリ起動からウィンドウ表示まで）                                            |
| 大容量ファイル | 数十MB級のテキストでも開いて快適にスクロールできる（表示範囲のみ描画する仮想化を前提とする） |
| 大規模フォルダ | 数万ファイルのフォルダを開いてもUIが固まらない（遅延読み込み）                               |
| 検索           | 検索中もUIが応答する。結果は逐次表示                                                         |
| メモリ         | 開いていないファイルの内容を保持しない。閉じたタブのデータは解放する                         |

【仮定】具体的な数値（「数十MB」「数万ファイル」）は目安。開発中に実測し、必要なら見直す。

### 5.2 配布・実行

- **ポータブル**：実行ファイルをコピーするだけで動作する。インストーラー不要
- Windows・macOS それぞれ向けにビルドし、単一ファイル（または最小限のファイル構成）で配布できること
- 起動速度のため、ReadyToRun や自己完結型の単一ファイル発行などを検討する
- レジストリや外部ランタイムのインストールに依存しない（自己完結型を前提）
- 設定ファイルは、実行ファイルと同じ場所またはユーザーのアプリデータ領域に小さなJSONで保存（【仮定】）

### 5.3 文字コード（【仮定】）

- 既定は UTF-8（BOM有無どちらも可）
- Shift_JIS（CP932）などを自動判定して表示できること。判定できない場合は文字コードを手動で選べる

### 5.4 その他

- 完全オフライン動作。テレメトリや外部通信は行わない
- ファイルを書き換える処理を一切持たない（安全性）

## 6. 定義ジャンプ・参照検索の仕様（簡易版）

意味解析（Roslyn 等）は使わず、**テキスト解析と名前一致ベース**で高速に動作させる。将来的に正確版へ拡張する。

### 6.1 定義ジャンプ（F-06）

1. カーソル位置の識別子（単語）を取得する
2. 開いているフォルダ内の C# ファイルから、その名前の宣言らしき行を探す
   - 対象の例：`class` / `struct` / `interface` / `enum` / `record` / `delegate` / メソッド・プロパティ・フィールド宣言
   - 正規表現（または軽量な字句解析）で検出する
3. 候補が1件ならそこへジャンプし、複数なら候補一覧を表示して選ばせる
4. 見つからなければ「定義が見つかりません」と通知する

### 6.2 参照検索（F-07）

- 識別子と**単語単位で一致**する箇所を、フォルダ内の対象ファイルから検索して一覧表示する
- コメントや文字列内の一致は区別できなくてもよい（簡易版の割り切り）
- 結果は「ファイル名・行番号・該当行」で表示し、選択でジャンプする

### 6.3 割り切り（簡易版の既知の制限）

- 同名のメソッド・型が複数ある場合、正しい対象を判別できない（候補を並べて選ばせる）
- オーバーロード、名前空間、継承による解決は行わない
- C# 以外の言語では、定義ジャンプは精度が落ちる、または非対応でもよい

### 6.4 将来拡張（今回の対象外）

- Roslyn による意味解析で、正確な定義・参照を解決する正確版
- 実装時は、簡易版と正確版を差し替えられるよう、**インターフェースで分離**しておく

## 7. 画面構成

```
┌──────────────────────────────────────────────────────┐
│ メニューバー（ファイル / 表示 / 検索）                 │
├────────────────┬─────────────────────────────────────┤
│ ファイルツリー  │ [タブ1][タブ2][タブ3] ...            │
│                │─────────────────────────────────────│
│ ▾ src          │ 1  using System;                    │
│   ▾ Models     │ 2  namespace Sample {               │
│     Foo.cs     │ 3      class Foo { ... }            │
│   Program.cs   │ ...   （構文ハイライト・読み取り専用）│
│                │                                     │
├────────────────┴─────────────────────────────────────┤
│ 検索結果 / 参照一覧パネル（必要なときだけ表示）         │
├──────────────────────────────────────────────────────┤
│ ステータスバー（パス / 行:列 / 文字コード）            │
└──────────────────────────────────────────────────────┘
```

- 左のツリーパネルと下の結果パネルは、表示・非表示を切り替えられる
- 結果パネルは、全文検索と参照検索で共用する

### 7.1 主なショートカット（【仮定】）

| 操作           | Windows      | macOS       |
| -------------- | ------------ | ----------- |
| ファイルを開く | Ctrl+O       | Cmd+O       |
| フォルダを開く | Ctrl+Shift+O | Cmd+Shift+O |
| 全文検索       | Ctrl+Shift+F | Cmd+Shift+F |
| ファイル内検索 | Ctrl+F       | Cmd+F       |
| 定義へジャンプ | F12          | F12         |
| 参照を検索     | Shift+F12    | Shift+F12   |
| タブを閉じる   | Ctrl+W       | Cmd+W       |

## 8. 開発フェーズ（推奨）

1. **Phase 1：骨格**　Avalonia プロジェクト作成、ウィンドウ、メニュー、単体ファイル表示（読み取り専用）
2. **Phase 2：表示の土台**　構文ハイライト、大容量ファイルでの性能確認、文字コード判定
3. **Phase 3：ツリーとタブ**　フォルダを開く、遅延読み込みツリー、タブ
4. **Phase 4：検索**　ファイル内検索（Ctrl+F）、フォルダ全文検索（非同期・キャンセル対応）
5. **Phase 5：定義ジャンプ・参照検索**　簡易版（名前一致ベース）、候補一覧UI
6. **Phase 6：仕上げと配布**　起動時間の計測と最適化、Windows/macOS 向けの単一ファイル発行、動作確認

各フェーズの終了時に、起動時間と大容量ファイル・大規模フォルダでの動作を確認すること。

---

## 9. 受け入れ基準

- [ ] 実行ファイルをコピーした別のPCで、インストールなしに起動できる（Windows / macOS）
- [ ] 起動からウィンドウ表示まで概ね1秒以内
- [ ] 数十MBのテキストファイルを開いてもスクロールが滑らかで、UIが固まらない
- [ ] 数万ファイルのフォルダを開いても、ツリーが素早く表示される
- [ ] ファイルを編集・保存する手段が存在しない
- [ ] 全文検索の実行中もUIが操作でき、キャンセルできる
- [ ] C# のクラス名・メソッド名で定義ジャンプと参照検索ができる（簡易版の制限内で）
- [ ] 複数ファイルをタブで開き、各タブでCtrl+F検索ができる
