# 行別試作のタブ・再読込・検索・終了

A-03承認範囲のA-04-03。通常表示/TabState/検索結果/位置とコピーの契約を維持し、以下は専用GUI試作だけへ接続する。

## 閲覧状態の保存

従来はタブを切り替えるたびDocumentDisplaySessionを作り直し、Caret以外の原文選択と独立閲覧位置を失っていた。専用試作のRowViewHistoryへAnchor/Caret/先頭原文行/横Offsetの数値だけを保存する。キーはDocumentHandleの参照同一性で、ConditionalWeakTableを使う。値にHandle/本文/投影/Leaseを持たせず、閉じた本文を保持しない。現在表示のHandle参照は交換/終了時に外す。通常表示では履歴を作らない。

同じHandleへ戻る場合だけ選択と閲覧位置を復元し、同じ位置を通知する直後の同期RestoreCaretではRevealを呼ばない。以後のGo To/検索/キー操作は明示Revealを使う。再読込や閉鎖後の再オープンは別Handleなので旧状態を適用しない。元のTabStateの位置/ピクセルOffsetへ論理行位置を混ぜない。

再読込/切替時は従来の単一入力受付をDetachし、捕捉・タイマー・コピーUI要求を失効させる。原文コピーの独立Leaseは既存契約どおり旧本文を読み終えられる。旧投影と古いバー操作は世代/参照照合で採用しない。

## ネイティブ統合試験

行別GUI CIの各入力で別の小さな入力を開き、2タブ間の選択/閲覧復元、非表示タブの表示Leaseなし、実際の再読込でのHandle交換/旧投影拒否/コピーLeaseの寿命を確認する。捕捉中のタブ切替と範囲外タイマー中の閉鎖を実行し、再オープンが新しい状態になることを確認する。

入力専用フォルダ（3つのcsだけ）を実際に開いてフォルダ検索を行う。非空入力では原文先頭のスカラーを検索し、ネイティブ結果ListBoxへのEnterを通して原文一致範囲へ移動する。直前には文末へ移動しておき、検索移動を検証する。空入力では存在しないトークンの結果が0件であることを確認する。Workspaceを閉じた後の結果行は再採用しない。試験中の再Attachから自動試験を再帰開始しないよう、ワークロードの起動は1回だけにする。

終了処理は通常のWindow.Closing→ViewModel.Stop→StopAndWaitを通す。完了後、最終のネイティブClose前に`*.shutdown.json`を別記録として作る。文書なし/タブ0/保留作業とコピー完了/弱履歴の消去/生存している旧Handleの解放とLease0を確認する。追跡Handleも弱参照だけで、検証が解放を妨げない。収集側はプロセス終了0とこの記録の両方を要求し、未生成・未完了・入力変化・失敗を成功扱いしない。終了フックと記録は専用ビルド/CI試験だけであり、通常配布へ含めない。

追加単体6ケースは空/Unicodeの選択と独立閲覧、同内容の別Handle/解放済みHandle拒否、値の更新/不正範囲/消去、所有スレッド、弱キーが本文を保持しないことを検証する。Python収集試験は実タブ/検索/再読込の証跡と終了記録を要求し、失敗/Timeout/終了記録なしで1回で停止することも検証する。

接続時間は文書世代ごとのRowAttachmentSamplesへ残す。元の単一DocumentAttachmentMillisecondsは最後の接続を表すため、初回や最大値の代用にしない。検証用の読み直し・検索・ハッシュ・文字列生成を含むGUI全体のCPU/割当は純粋な描画測定ではない。物理入力/物理描画、Bidi/結合列/タブの視覚幅、大規模10/50/100 MiB・5文書と文法の固定予算はA-04/A-05/G2へ残す。
