# 行別試作の全文スクロール接続

A-03承認範囲のA-04-03。通常UIは従来表示を維持し、以下はCodeViewPerformanceProbe=trueとCODEVIEW_GUI_ROWS=1でのみ利用する。

## 原文範囲

行別試作にだけ最大行長の取得を明示指定する。DocumentBuilder.Completeで既存の最終行索引をワーカースレッド上で1回たどり、改行を除いた最大行長（UTF-16単位）をDocumentHandleへ不変の値として保存する。処理量は行数に比例し、本文再走査/全文コピー/永続索引を増やさない。DocumentDisplaySessionは同じ値を参照する。

既定のAdapter/Builderは取得OFFで、通常表示に行数比例の走査を加えない。未取得はnull、取得済みの空文書は0で区別する。スクロール側が未取得値を空行長と誤認せず拒否する。専用ビルドの構成箇所でCODEVIEW_GUI_ROWS=1のときだけ取得ONのAdapterを渡す。通常行/巨大1行の50 MiB構築を、同じ構築クラスの取得OFF/ONで比較する。挿入/所有/範囲検査/Undo/スナップショット/保持形式は共通であり、入力デコード/I/O・アプリ起動を含む比較ではない。

専用GUIではEditorを初期化時（原文のBinding前）にGridで囲み、独立した縦横ScrollBarを置く。縦は原文1〜最終行、横は0〜最大行長で、最終行/挿入位置を先頭に置くところまで移動できる。表示用の短い文書の範囲を原文の全範囲と解釈しない。ネイティブの局所スクロールバーは無効にし、内部Offsetを0へ保つ。値の同期中はValueChangedを再受付せず、文書切替後は現在のセッションだけを読む。バー操作開始時の文書世代が古ければ値を採用せず元へ同期し、解放の後着は操作トークンで拒否する。解放時はネイティブThumbの処理後まで世代を保ち、最後の更新が新文書へ紛れ込まないようにする。

横位置は論理UTF-16である。タブ/絵文字/結合文字/Bidiの物理幅を索引化していない。明示Reveal後に有界な表示内Caret矩形が横へ外れる場合だけ、原文Caret列を左端へ置く有界な再投影を1回行う。巨大行の非表示prefixは測らない。視覚列の連続した横移動・省略位置でのタブ整列・Bidi/結合列の完全対応は後続の評価に残す。

文脈付き表示を有効にした場合、明示移動後に使うCaretの横位置は、該当行の描画と同じ配置から求める。文脈付き配置のない行では既存のエディターのCaret矩形を使う。

## 入力と寿命

ホイール/トラックパッドは縦3行・横16 UTF-16単位/Deltaを基準に、小数をイベント間で蓄積する。Shiftは縦Deltaを横へ加える。1イベントの処理は縦512行/横4,096単位までに制限し、巨大Deltaの残りを将来へ溜めない。NaN/Infinityは残った小数も変更せず無視する。文書交換時は小数をリセットする。スクロールバー/ホイールの閲覧は原文Anchor/Caretと選択/コピーを変更せず、明示Revealを呼ばない。

行別クリック/ドラッグ/行番号選択は既存のBoundedPointerSelectionと単一の捕捉/40 msタイマーへ接続する。範囲外では既存の原文移動と明示Revealを使用する。旧投影/他ポインター/捕捉喪失を拒否し、DetachInteractiveでタイマー・捕捉・入力購読を解除する。切替/終了で別の所有者を増やさない。

文脈付きの行では、本文領域内の余白をクリックしたときも、最も近い描画範囲から原文位置を求める。短い左書きの行の右側をクリックすると行末に移動し、ステータス欄には原文の行・列が出る。

## 検証結果

追加単体は最大行長9ケース（全分割位置、混在改行、Unicode、空、ワーカー移譲/解放/異常）、ホイール6ケース（小数、Shift/斜め、巨大値、非有限、リセット）。既存の行別原文対応/選択/寿命の単体も維持する。

行別GUI CIは以前の3入力×3独立プロセス/OSに加え、原文ScrollBarの最大値・先頭末尾移動・コピー不変、ルーティングした小数/Shift/斜めWheel、ポインターの捕捉/ドラッグ/範囲外タイマー/解放/捕捉喪失、Detach/再Attachを検証する。64回の閲覧変更もScrollBar.Valueを経由する。これらはコントロールへのルーティングで、OSの物理入力を注入した試験ではない。Detachの確認からタブ切替/再読込/終了の全統合受入済みとは推定しない。

コアCIでは両OSで原文位置16ケース+最大行長9ケース、従来の有界投影予算と構築比較を独立3プロセス/OSで直列実行する。構築比較は各形状の50 MiB入力をABBA順に4回計測外で事前実行してから、通常行/巨大1行の各3組をAB/BA/AB順で行い、CPU・割当・GC・OSメモリ前後・全構築/Complete時間を記録する。初回の小入力の事前実行や別クラスの基準複製による比較は、初期化/最適化の影響が混在するため最終判定に使わない。メモリはピークではなく、別OS間で互換な指標でもない。固定入力/予算による大規模GUI性能、物理操作、検索/タブ/再読込/終了・文法はA-04/A-05/G2へ残す。

`d9b117c`で両OSの機能/コア/通常試験・通常GUI回帰・Windows Native AOTが成功した。[原記録とコスト比較](validation-results/2026-11-06-row-scroll/README.md)。行別GUIの接続最大はWindows 143.184 ms、macOS 117.367 msで既定100 msを超え、A-05/G2の性能受入は未完了である。A-04-03-01は制御の接続/検証までの完了とし、実際の切替/再読込/検索/終了と物理入力・視覚幅の受入は残す。
