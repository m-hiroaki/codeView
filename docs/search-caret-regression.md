# 検索ジャンプの同期Caret復元

検索結果の移動先は確定していても、SetPositionの同期通知中に古いCaret通知が入ると、画面側の_line/_columnが古い値へ戻ることがある。行別試作では表示文書の通知を原文Caretへ補正するため、遅延した選択より前のRestoreCaretが旧文末を指していた。最終的なSelectSearchRangeだけを見る従来の試験では検出できなかった。

RestoreCaretへ確定済みのDocumentMove.Positionを直接渡す。表示通知の補正、原文位置/検索結果/選択契約、イベント順、外部APIとレイヤは変更しない。新しい保持/走査/ワーカーを加えず、旧位置への余分な復元と再描画を防ぐ。性能改善率やWindows初回接続100 ms達成を、この修正から推定しない。

追加の単体3ケースは通常の一致・次行境界・外部変更で選択を抑制する場合を対象に、Position通知の途中へ旧位置を再入させる。確定移動先がRestoreCaretへ届き、その後にSelectSearchRangeが通知されることを確認する。修正前は3件とも旧位置になって失敗した。

行別ライフサイクル試験も、文末から実際の検索結果Enterを通し、同期RestoreCaret直後の原文Caretを捕捉して、遅延選択とは別に照合する。修正前`d2c8cd8`の両OS CIはsearch-caret-before-deferred-selectionで失敗した。本文/タブ/コピー/終了の従来受入は維持する。

Unicode文脈の追加索引/Controlはこの修正には含めず、2026-11-06に別途承認された追加設計案の実装検証で進める。設定保存や通常UIへの行別採用も行わない。

`f0546ed`で新規3ケースを含む検索移動23件と、通常試験macOS .NET753/Python108・Windows .NET750+既存3スキップ/Python88+既存20スキップが成功した。両OS各9ネイティブプロセス/1,674検証、非空6回/OSの同期Caret照合と終了後解放も成功。[修正前後の原記録と限界](validation-results/2026-11-06-search-caret/README.md)。Windows接続100 msやUnicode視覚未達は解消したことにしない。
