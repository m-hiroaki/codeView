# 50 MiB本文の有界表示・全文表示のGUI比較

2026-10-31 JST。ソース `9b994ee`、製品ソース変更なし。専用計測ビルドのみ使用。Macのロック解除後、通常のAvaloniaネイティブウィンドウで実行した。ヘッドレス描画ではない。G2の採用判定は未完了。

## 条件と再現

- macOS 27.0.1 arm64、32 GiB、.NET 10.0.12、Avalonia 12.1.3 / AvaloniaEdit 12.0.0。1180×800 DIP、scaling 2、文法なし。
- 同じ生成済みUTF-8 50 MiBの単一行と通常改行。各入力を事前に1 MiBずつ全読込し、Warm条件で各3回、新プロセスで順次測定した。Cold I/O・OSプロセス開始からの起動時間は測っていない。
- ビルド・単体試験は正式9回の計測と重ねていない。他のユーザーアプリや以前の試験アプリは稼働したままであり、専用ベンチマークOS環境ではない。
- [手順](../../performance-plan.md#6-ネイティブguiの代理指標の測定)で専用ビルドを作り、`artifacts/dev/codeView-window-probe.app/Contents/MacOS`へ配置。`CODEVIEW_GUI_PERF_REPORT`に未使用の絶対パス、`CODEVIEW_PERF_CACHE=warm-explicit-source-read`、`CODEVIEW_GUI_WINDOWED=1`（有界）または`0`（全文）を指定し、入力ファイルの絶対パスをCLI引数で渡した。
- 有界表示は元本文全域をReadLeaseとともに保持し、初回と64回の移動ごとに最大16,384 UTF-16単位の表示文書を生成する。長行では先頭からEOFまで原文39,945,760単位を移動した。原文は切り捨てていない。

## 結果

各値は3回の範囲。メモリは10msサンプルの `macOS.phys_footprint` 増分、CPUはプロセス全体の累積である。

| 入力・表示 | 接続同期 ms | 64回中の同期移動最大 ms | tick間隔最大 ms | メモリ増分 MiB | CPU ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| 単一長行・有界 | 45.81–45.94 | 42.08–44.91 | 51.55–53.17 | 331.80–338.31 | 3,134–3,317 |
| 通常改行・有界 | 7.64–7.86 | 7.80–11.66 | 17.28–17.51 | 336.36–341.52 | 2,039–2,081 |
| 通常改行・全文 | 88.58–91.31 | 0.65–0.76 | 17.81–19.05 | 499.58–513.75 | 2,027–2,041 |

正確な値は [summary.json](summary.json) と各実行のJSON/標準出力ログ、入力ハッシュは [inputs.json](inputs.json)、ソース/計測DLLハッシュは [provenance.json](provenance.json) を参照する。

接続100msとメモリ512 MiBの事前予算に対して、有界表示は両入力とも3回合格。通常改行の全文表示は接続3回合格、メモリは2回合格・1回未達であり、安定して予算内とは判定しない。初期のサンプルなしの良好な結果を、このピーク測定に優先させない。

全条件で100ms超のtick間隔はなかったが、16.7ms目標は超過した。特に長行の有界表示は約52–53msで、60fps目標を満たしたとは扱わない。全文表示の長行は既存の接続約27.7秒・footprint約9.3GBの未達結果を再利用し、今回再実行していない。同一版/同一時刻の比較ではないため、改善倍率は算出しない。

## 判定と残件

表示範囲を絞る方式は長行の時間・メモリ問題を軽減する候補として継続する。通常改行では全文表示の移動が速く、有界表示には表示文書を作り直すコストがあるため、全面的な置換の根拠にはしない。表示量や再利用方式の比較と、通常本文を含む保持量の是正を続ける。

測定はScrollTo/EnsureVisualLinesの同期区間とRequestAnimationFrameコールバック到達の代理指標であり、物理画面の描画完了、キーボード/マウス応答は未測定。GC世代/割当/個別停止のトレースも今回のGUI測定には含めていない。試作の原文座標、行番号、選択/全文コピー、スクロールバー、文法状態は製品仕様に未接続。10/100 MiB・別文字コード・複数タブ・Windowsもこの結果の保証対象ではない。

通常製品ビルドを再構築し、既存の有界切出しの正常/不正/Unicode・CRLF境界試験を含む通常単体444件が合格（失敗0・スキップ0）。今回、製品コードや試験ロジックは変更していない。G2およびA-02全体のチェックは付けない。
