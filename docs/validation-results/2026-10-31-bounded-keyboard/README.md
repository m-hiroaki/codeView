# 有界表示の実キー入力・原文ステータスと長行の一致位置可視化

2026-10-31。`0e1a3ae`からの差分。通常UIへの有界表示採用は未完了。キーボード専用試作と、通常UIの検索ジャンプ修正を区別する。

## 実装と単体試験

専用ビルドの`CODEVIEW_GUI_INTERACTIVE=1`で、原文モデルの左右/論理行/行頭末尾/文頭末尾・選択拡張/全選択/解除を実キーへ接続した。表示窓内にある間は文書を再利用し、端付近で原文から作り直す。ステータスと保存する行列は原文を使う。原文位置の復元は範囲を収め、サロゲート対/CRLF途中を補正する。

文書切替では入力ハンドラー/表示Leaseを解放し、遅れた初期描画は世代で不採用にする。レイアウト後のスクロールは最新セッション/窓/キャレットだけを参照する1件へ集約し、旧本文をキャプチャしない。入力・スクロールの詳細記録は各256件まで、総件数は別に数える。実装は比較用計測器内に置き、通常製品には含めない。採用時は表示/入力責務をPresentationへ移し、計測器への依存を残さない。

Release通常単体536件合格・失敗0・スキップ0（`bounded-keyboard-normal-final.trx`）。追加31件はキー割当27件と原文行列復元4件。Windows/macOSの割当、選択拡張、対応外の修飾キー、誤った局所コピーを許可しない扱い、巨大行列/不正な既定位置/Unicode境界を確認した。通常製品にキー割当の試作型が入らないことも確認した。Windowsの実キー受入ではない。

## 入力と実キー確認

macOS 27.0.1 arm64、.NET 10.0.12、Avalonia 12.1.3 / AvaloniaEdit 12.0.0、表示上限1,024 UTF-16単位。入力はUTF-8の生成ファイル10,435 bytes・8,033 UTF-16単位・5行。2行目は8,008単位で日本語/絵文字を含み、末尾に`END😀`を置いた。[マニフェスト](input-manifest.json)に内容ハッシュを保存し、試験後も一致した。実キーはCua経由、画像は加工していない。

最終版`bounded-keyboard-caret-20261031.json`で次を確認した。

- Down→Endで原文2行8009列へ移動し、表示Sliceを越える列番号を維持。
- Shift+Leftで末尾の絵文字を分断せず8007列、Shift+Homeで2行1列まで原文8,008単位を逆方向選択。[選択画面](cross-window-selection.png)、[AX](cross-window-selection.ax.txt)。
- End→Down→Downで3行2列、4行13列へ収め、Up→Upで元の2行8009列を復元。
- 全選択は原文全8,033単位、Escapeで解除。文頭から右移動/選択拡張も維持。
- コピー未接続のCtrl+Cでは診断表示とし、原文選択2単位を保持。OSクリップボードの内容を確認した試験ではなく、コピー機能完成の証拠にはしない。
- 22件の処理を記録し、同期ハンドラー区間最大2.153ms。レイアウト後の可視化は23回、EnsureVisualLines/BringCaretToViewの同期区間最大2.695ms。記録した全キャレット矩形がビューポート内に入り、長行末尾の水平Offsetは約7,740.61 DIP。[末尾画面](original-column-8009.png)、[AX](original-column-8009.ax.txt)で`END😀`と原文ステータスを確認した。
- ClosedとCLI終了コード0。経過時間は目視/操作待ちを含み、起動/入力応答の速度には転用しない。上の同期区間はキー受信から物理描画までの遅延ではない。

対象は小さい生成入力で、50 MiB/100 MiBや多数タブの性能合格ではない。原文行番号/全面仮想スクロールバー/可視行数を満たす表示、マウス選択・ドラッグ中入替・コピー/クリップボード、結合列/双方向、タブ切替/再読込の包括受入、IME、別OS/長時間利用は残る。試作ではマウスクリックはフォーカスだけにし、未接続のドラッグ選択を始めない。対応外のキー/コピーを通常製品で禁止する設計ではない。

## 入力診断と横スクロール未達の記録

初回`bounded-keyboard-20261031.json`ではCommandを含む操作の前に全選択が入り、行末移動が文末へ変わった。`bounded-key-diagnosis-20261031.json`で、余分な操作がRawKey=A / PhysicalKey=A / Meta / 文字属性ありとして届いたことを確認した。修飾キー単体の誤認だという証拠はなく、どの層で追加されたかは未確定である。正当な全選択を壊すフィルターを加えず、Home/Endで行頭末尾を確認した。Command+左右のクリーンな実キー受入は残す。Command+Aは複数回届いたが全選択は冪等であり、1回の送信で1イベントだったとは主張しない。記録はキー種別/修飾/文字属性の有無だけで、文字属性の値は保存しない。

`bounded-keyboard-final-20261031.json`は原文移動/選択/行列表示を確認した22件だが、[末尾画面](before-postscroll-column-8009.png)では横スクロールが追い付いていなかった。遅延実行だけを加えた`bounded-keyboard-verified-20261031.json`でも水平Offset 0のままであった。これらを可視化成功には含めない。

上流[12.0.0のScrollTo](https://github.com/AvaloniaUI/AvaloniaEdit/blob/12.0.0/src/AvaloniaEdit/TextEditor.cs#L1246)は水平目標を0へ戻している。試作をレイアウト後の[Caret.BringCaretToView](https://github.com/AvaloniaUI/AvaloniaEdit/blob/12.0.0/src/AvaloniaEdit/Editing/Caret.cs#L423)へ替え、最終の矩形/実画面確認へ進んだ。旧ScrollTo/EnsureVisualLinesの時間や訪問した原文Offsetは、ターゲットがピクセル上でも見えた証拠にはしない。過去の生データは書き換えず、G2採用前の未検証事項として補足する。この対処はキーボード専用試作であり、旧来のポインター選択中の再帰障害を修正した証拠ではない。

## 通常製品UIの検索ジャンプ

同じAPI制約が通常UIにも当たるため、既存のLoaded/世代/入力検証後の選択処理へEnsureVisualLinesとBringCaretToView(40)を追加した。既存の縦方向位置決めを保ち、40 DIPの文脈余白で短い一致が右端へ隠れないようにする。ソース読込/検索ワーカー/起動時の処理は増やしていない。巨大な一致全体が常に画面に収まる保証ではない。

通常Releaseビルドで生成フォルダを開き、検索欄の実際の値`END`で検索、確定結果1件の抜粋をダブルクリックした。原文2行8004列、1タブ、本文内で`END`の3文字選択とフォーカス、水平Offset約69,930.54 DIPを確認した。[最終画面](normal-long-line-result.png)、[AX](normal-long-line-result.ax.txt)を保存し、CLI終了0を確認した。余白なしではキャレットが右端に入っても一致文字が隠れた[途中画面](normal-jump-before-context.png)も残す。

このスクロールは実デスクトップのレイアウトが必要で、通常NUnit環境だけでは実コントロールの可視性を検証できないため、追加テスト基盤を導入せず上のネイティブ試験で確認した。通常単体536件は既存の移動/世代/破棄/検索を含めて回帰確認した。IME入力・絵文字の検索欄入力の受入を完了したとは扱わない。試験ログにはmacOS IMKのmach portメッセージもあり、その機能影響はこの試験から断定しない。

## 再現と版の区別

専用ビルドで、入力ファイル1件をCLI指定し、`CODEVIEW_GUI_WINDOWED=1 CODEVIEW_GUI_WINDOW_CHARS=1024 CODEVIEW_GUI_INTERACTIVE=1 CODEVIEW_GUI_PERF_REPORT=<未使用の絶対パス>`を設定する。自動64ステップは実行せず、ウィンドウ閉鎖時に報告する。通常ビルドにはこのモードを含めない。計測用ビルド手順は[性能計画](../../performance-plan.md)を参照する。
