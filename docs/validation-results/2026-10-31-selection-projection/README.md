# 原文移動・選択の可視部分への変換とGUI反映

2026-10-31。`8657ef0`からの差分。通常製品UIへの有界表示の採用は未完了。今回は原文移動モデルと、専用GUIでの選択色までを接続した。

## 実装と通常試験

原文での左右移動、論理行移動（短い行をまたぐ希望列の復元）、行頭末尾・文頭末尾、選択拡張を実装した。左右はサロゲート対/CRLFを分断せず、非拡張なら選択の指定方向の端へ畳む。結合列/双方向文字の視覚的なキー移動は保証しない。

最新Sliceへの選択変換は原文Anchor/Caretを変えず、可視Start/Length・方向・切詰め有無と、可視なら局所Caretを返す。Slice外Caretはnull。可視部分は表示Sliceとの交差を指し、1,024文字が物理画面に同時に収まるという意味ではない。古いSliceの変換は拒否する。全選択が1,024文字に縮んだと扱わず、コピーは元の範囲を維持する。

Release通常単体505件合格、失敗0・スキップ0（`source-selection-verified.trx`）。前回から28件追加した。原文移動/選択変換18件、GUI操作計画2件、終了コード保持8件を含む。空/EOF/前後の画面外選択、順/逆方向、サロゲート/CRLF、巨大な行移動量、不正方向/古いSlice/破棄済み、コピー済み範囲の保持を確認した。通常製品に計測型が含まれないことも確認した。

## 50 MiBの原文モデル性能

macOS 27.0.1 arm64、32 GiB、.NET 10.0.12、Release。各入力1回、新テストプロセスで順次測定し、ビルドを並走させていない。本文構築後のメモリ上の処理でありCold/Warmストレージ比較ではない。測定手順と事前予算は[性能計画8.1](../../performance-plan.md#81-原文座標選択コピーの統合基盤)を参照する。

全選択のコピーLeaseを固定してから、先頭で右5万回・左5万回の選択拡張を行った。コピーは表示と原文ハンドルを閉じた後に実行し、事前の全域走査と文字数/加算チェックサムを照合した。

## ネイティブGUIの選択表示

50 MiBの同じ単一長行（39,945,760 UTF-16単位）、表示上限1,024、文法なし、1180×800 DIP/scaling 2。入力を事前全読込したWarm条件で、原文コマンド64ステップを実行した。文頭/末尾、逆方向全選択、全選択、窓をまたぐ拡張を含み、各回の実エディターのSelectionStart/Length/Caretを変換結果と照合した。物理キー/ポインター入力は注入していない。

- 接続11.08ms、同期処理最大11.84ms、tick間隔最大47.04ms、phys_footprintサンプルピーク増分約297.56 MiB。
- 最終原文選択はOffset 0から39,945,760単位、原文Caretは1行39,945,761列。
- 実エディターへは表示Slice内の1,024単位だけを選択として渡し、最終の局所Caretは1,024。逆方向全選択では局所Caret 0も確認した。
- 64ステップ完走、測定中の入力による中断なし、測定後の画面で青い選択色を確認した。[画面](visible-selection.png)と[AX](visible-selection.ax.txt)、[全ステップのJSON](source-selection-projection-final-20261031.json)、[ログ](source-selection-projection-final-20261031.log)を保存した。
- 画面確認のため報告後もウィンドウを保持し、確認後に閉じた。ClosedとCLI終了コード0を確認した。保持/画面確認の約30秒は上の計測値に含まない。終了直後のAX取得では空の試験画面が再表示されたため、それも閉じた。CLI実行の完了はAX表示ではなく実行セッションの終了コードで判定した。

接続100ms/メモリ512 MiBは予算内で、tick100ms超はなかったが、16.7ms目標は未達。単発の代理指標で物理描画の60fpsや入力応答を合格にしない。原文ステータス/行番号/スクロールバー/タブ位置には未接続で、画面下の列1025は局所座標のままである。実キー/マウスによる選択・境界横断、選択中入替の再帰障害、OSクリップボード、結合列/双方向/タブ、別規模/OS/長時間利用が残る。通常UIへこの試作を採用していない。

再現は専用GUIビルドで`CODEVIEW_GUI_WINDOWED=1 CODEVIEW_GUI_SELECTION=1 CODEVIEW_GUI_WINDOW_CHARS=1024`を指定する。`CODEVIEW_GUI_PERF_REPORT`は未使用の絶対パスとする。画面確認時だけ`CODEVIEW_GUI_HOLD_AFTER_REPORT=1`を加える。これは計測後の目視用で、対話的な原文操作を接続するモードではない。保持時間は測定外、手動で閉じた後の終了も別途確認する。

## 入力による中断と終了コードの修正

最初の実行は4ステップで入力の混入を検知し、`Failure=physical-input-during-probe`で中断した。[報告](interrupted-before-exit-fix.json)を残し、性能結果から除外した。ツールが観測した終了コードは0だった。どの物理入力だったかは初回ログに記録しておらず未確定である。

Environment.ExitCodeだけで保持した失敗は、後続のUI終了処理で上書きされ得る。Program内のProcessExitStatusへ失敗を記録し、Mainの戻り値へ反映するよう修正した。既存の明示的な非0コードは優先し、UI致命的通知/後始末/ドロップの未知障害と計測器の失敗が同じ入口を使う。例外の収集機構や新しい層は追加していない。今後の入力中断ログは文字内容を含めずイベント種別だけを記録する。

最終版は存在しない生成用入力を渡して`open-failed`を発生させ、Closed通知と終了コード1を確認した。[失敗報告](source-selection-open-failure-20261031.json)と[ログ](source-selection-open-failure-20261031.log)を保存した。正常終了0と失敗1を実機で区別できた。入力中断そのものを意図的に再注入した試験や、すべてのUI未知例外経路のネイティブ注入試験が完了したとは扱わない。
