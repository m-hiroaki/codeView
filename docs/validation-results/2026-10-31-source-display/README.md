# 有界表示の原文位置・選択・逐次コピー基盤

2026-10-31。`0b3de7d`からの作業差分。通常UIへ未採用のDocuments内モデルと専用GUI比較試作を検証した。G2/A-02は未完了。

## 実装と単体試験

`DocumentDisplaySession`が原文のAnchor/Caretを保持し、表示Sliceの入替と切り離した。Sliceには原文先頭Offset/行列・目標Offsetがあり、最新インスタンスだけが局所イベントを原文位置へ変換できる。逆方向選択、全選択、原文のサロゲート対/CRLF境界の補正を扱う。

`BeginCopy`は選択範囲と独立ReadLeaseを固定する。表示セッションや元の本文ハンドルを閉じても、そのコピーは元の選択を読み出せる。ワーカーで最大16,384 UTF-16単位ずつTextWriterへ渡し、全文の中間文字列を作らない。コピー元や出力先を編集/閉鎖しない。出力先への同期Write自体が取消不能なら強制終了できない。

Release通常単体477件合格、失敗0・スキップ0（`display-session-verified.trx`）。追加13件で次を確認した。

- 複数の表示窓にまたがる選択と原文全体のコピー、元の行列、逆方向選択。
- 同値の旧Slice・他セッション・複製からの遅延イベント拒否。
- サロゲート/CRLFの全位置、空文書/EOF、範囲外/64bit上限/表示量上下限、不正要求で既存選択を変更しないこと。
- UI所有スレッドの検証、コピーのワーカー実行、後続選択変更/表示破棄/本文閉鎖後の不変スナップショット、二重Dispose、破棄済みセッションが元ハンドルを保持しないこと（強制GCは試験内のみ）。
- 大きな範囲の内容と順序、最大Writeサイズ、事前/途中取消、出力先例外の伝播、出力先を閉じないこと、Lease解放。

最初の通常試験で1件、CRLF直後の有効境界を補正対象とした試験期待値の誤りがあった。サロゲート途中とCRLF途中を別の明示入力に修正して、最終477件を確認した。

## 50 MiBの原文モデル測定

macOS 27.0.1 arm64、32 GiB、.NET 10.0.12、Release。生成済み入力をデコードして本文を構築し、1,024単位のSliceを先頭〜EOFの64箇所で生成した。別走査のUTF-16単位数/加算チェックサムとコピー出力を照合した。文字列との内容/順序の完全比較は上の通常単体試験で実施する。数値チェックサムを暗号学的な同一性証明にはしない。

表示セッション/本文ハンドルを解放してから、コピーを数値加算するTextWriterへ全選択範囲を流した。入力構築・事前検証・レポート生成と最終クリップボード文字列はコピー計測外。各入力1回・新しいテストプロセスで順次実行し、ビルドは並走していない。キャッシュを制御したストレージI/O比較ではなく、メモリ上の文書モデルの測定である。

| 入力 | 原文UTF-16単位 | Slice最大 ms | 64回割当 bytes | コピーLease取得 ms / bytes | 全文コピー ms / CPU ms | コピー割当 bytes |
| --- | ---: | ---: | ---: | --- | --- | ---: |
| 単一長行 UTF-8 | 39,945,760 | 0.804 | 211,216 | 0.029 / 200 | 48.80 / 49.28 | 872 |
| 通常改行 UTF-8 | 30,980,684 | 0.763 | 210,376 | 0.029 / 200 | 40.89 / 41.39 | 872 |
| 通常改行 CP932 | 38,947,124 | 0.747 | 210,736 | 0.028 / 200 | 46.73 / 47.18 | 872 |

コピー区間のGC停止/Gen0/1/2は全条件0。元本文構築でプールが利用済みの条件である。コピー割当には区間内の計測用処理も含む。最大Writeは16,384以下で、コピーDispose後のLease数は全条件0。事前の[性能予算8.1](../../performance-plan.md#81-原文座標選択コピーの統合基盤)に3件とも合格した。全スレッド割当やOSメモリ/個々のGC停止の測定ではない。

再現は`CODEVIEW_PERF_DISPLAY_FILE=<生成済み入力>`、`CODEVIEW_PERF_LABEL=<任意のASCII英数字/ハイフン>`を設定し、`dotnet test codeView.slnx -c Release --no-build --filter FullyQualifiedName~DocumentDisplayPerformanceTests`を実行する。JSONはこのフォルダの`display-session-verified-*.json`に保存した。ソース・入力・アセンブリハッシュは[provenance.json](provenance.json)を参照する。

## 専用ネイティブGUIへの接続確認

専用GUI試作の切出し経路を、このDocumentsモデルへ接続した。通常製品のエディターは従来のままである。50 MiB長行、表示量1,024、64箇所移動を1回確認した。

- 接続10.19ms、同期移動最大10.30ms、tick間隔最大17.86ms、メモリ増分約292.06 MiB。
- 最終の原文Caretは39,945,760、原文位置1行39,945,761列、原文選択は先頭から全39,945,760単位。最大表示量1,024を維持した。
- 入力による計測中断なし、Closed通知と終了コード0を確認。[生JSON](source-display-session-verified-20261031.json)と[ログ](source-display-session-verified-20261031.log)を保存した。

選択はモデルの論理状態のみで、画面の選択色・原文行番号・ステータス・マウス/キー入力・OSクリップボードには未接続である。物理画面の描画完了や入力応答を測ったことにはしない。過去の選択中入替の再帰障害が直った証拠でもない。可視行数/長行内スクロール/タブ位置保存・再読込、文法、別文字コードの実GUI、Windows/長時間利用を引き続き検証する。
