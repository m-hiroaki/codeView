# 有界表示の原文行番号

2026-10-31。`edf45e0`からの差分。表示窓の局所行番号を原文行番号へ対応させた。通常UI採用、全面スクロール/可視行数と他のG2/A-02のゲートは未完了。

## 変更と所有

専用GUIの既存LineNumberMarginをSourceLineNumberMarginへ置き換える。SourceLineNumbersは先頭原文行・原文全行数・表示行数だけを保持し、表示行nを先頭原文行＋n−1へ変換する。生成時と取得時に範囲を検証し、64bit上限でも加算をあふれさせない。桁幅は原文全行数から計算して同じ本文の窓切替では固定する。描画は可視VisualLineだけで、原文の全行走査/ラベル一覧を作らない。

初回・対話での窓交換・自動移動・選択投影の全生成経路で、表示文書と数値対応を一緒に更新する。余白は短い表示文書1件を保持し、TextView.Documentが同じ場合だけ描画する。原文/ReadLease/タブを追加で保持せず、クリア時は参照と数値対応を解除する。通常ビルドには含めない。

[固定版の標準余白](https://github.com/AvaloniaUI/AvaloniaEdit/blob/12.0.0/src/AvaloniaEdit/Editing/LineNumberMargin.cs)は表示用文書の行番号を使うため、そのままでは窓の途中で1へ戻る。既存余白の計測/フォントと可視行の描画位置を使い、ラベル値と原文に基づく幅を接続した。理由・利点/コスト・影響・移行は[詳細設計04の6.7](../../detailed-design/04-documents-tabs.md#67-有界表示の原文行番号専用試作)を参照する。

## 単体とコンパイル

Release通常590件合格・失敗0・スキップ0（`source-line-numbers-normal.trx`）。追加21件は先頭/途中/末尾/long.MaxValueの変換5、原文全行数による桁境界7、不正対応5、未接続/範囲外1、全切出しの原文照合3。

空本文、日本語/絵文字、CRLF/CR/LF/末尾空行を含む原文の各位置で表示窓を作り、表示文書の全行先頭を原文GetLocationと照合した。単体ではラベルの数値・幅・境界を検証する。フォント/ピクセル描画はデスクトップのレイアウトが必要なため専用GUIで確認し、このためだけの新しいテストフレームワークは追加していない。専用GUIは警告0・エラー0でコンパイルした。

## 小さい生成入力の実画面

[入力情報](input-manifest.json)の3ファイルをCLIで同時に開いた。いずれもUTF-8で、生成後のハッシュが試験後も一致した。

| ファイル | bytes | UTF-16単位 | 原文行数 |
| --- | ---: | ---: | ---: |
| long.cs | 24,302 | 21,900 | 1,002 |
| normal.cs | 14,000 | 14,000 | 1,001 |
| empty.cs | 0 | 0 | 1 |

再生成する場合は未使用のフォルダへ、次の文字列をUTF-8で保存する。long.csの1000行目は8,008 UTF-16単位、normal.csはCRLFで終わる。

```python
long_text = "\n".join([f"// header {i}" for i in range(1, 1000)] +
    ["// " + "sample = 123; 注文😀; " * 400 + "END😀", "// last line", ""])
normal_text = "\r\n".join([f"// line {i:04}" for i in range(1, 1001)] + [""])
empty_text = ""
```

CODEVIEW_GUI_WINDOWED=1 / CODEVIEW_GUI_INTERACTIVE=1 / CODEVIEW_GUI_WINDOW_CHARS=1024と未使用の絶対報告パスを指定し、生成フォルダ・long.cs・normal.cs・empty.csをCLI引数で渡した。Mac実機で次を確認した。

- [空文書](empty.png)は行番号1、原文ステータスも1行1列。
- long.csを選び、文末→2回上→行末で原文1000行8009列へ移動。[画面](long-1000.png)は長行途中の局所1行目を1000と描き、次の短い行と末尾空行を1001・1002と描く。
- normal.csの文末へ移動。[画面](normal-eof.png)は970〜1001の原文行番号を表示し、ステータスは1001行1列。桁数3/4の混在を4桁幅で右揃えする。
- [空文書へ切替](empty-after-switch.png)で旧番号は残らず1へ戻る。[長行へ復帰](restored-long.png)で原文1000行8009列と1000〜1002のラベルが復元される。
- 非選択タブを閉じても現在の表示を維持し、[全タブ閉鎖](all-tabs-closed.png)でラベルと位置表示が消える。

各画面と同名のAXを保存した。[報告](source-line-numbers-20261031.json)/[ログ](source-line-numbers-20261031.log)でラベル描画171個、閉鎖後の対応IsValid=false・最初/最後ラベルnull、Closed/CLI終了0を確認した。最初のgetAppが653.367秒後に応答したため、この対話セッションのCPU/メモリ/経過を性能比較に使わない。セッションは再起動せず、同じウィンドウで検証を終えた。

## 50 MiBの描画経路比較

前回コミットの専用GUIバイナリと今回版を、同じ生成済み50 MiB長行/通常UTF-8・Warm条件・表示1,024単位で各1回、新プロセスで順次実行した。事前に入力を全読込し、ビルド/単体試験は並走させていない。macOS 27.0.1 arm64 / .NET 10.0.12 / 1180×800 DIP / scaling 2、文法なし。他のユーザーアプリも動く環境である。[比較スクリプト](compare.py)と[集計](line-numbers-comparison-summary.json)、各生JSON/ログ、入力マニフェストを保存した。

4回すべて64回移動・訪問65個・表示上限1,024・入力中断なし・Closed/終了0。旧版のDLLハッシュは前回のprovenanceと一致することを実行前に確認した。

| 入力/版 | 接続 ms | 同期移動最大 ms | tick最大 ms | メモリ増分 MiB | CPU ms | GC停止合計 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 長行/前回 | 10.416 | 13.706 | 28.314 | 279.59 | 1,196.873 | 78.780 |
| 長行/今回 | 10.442 | 9.987 | 17.623 | 291.64 | 1,170.001 | 70.038 |
| 通常/前回 | 7.379 | 11.506 | 17.189 | 329.50 | 1,888.396 | 106.664 |
| 通常/今回 | 7.851 | 7.828 | 17.582 | 336.13 | 1,880.244 | 103.915 |

合計割当は長行286,186,752→286,447,488 bytes（＋260,736）、通常339,531,912→339,802,992 bytes（＋271,080）。Gen0/1/2はそれぞれ37/14/3と43/16/3で前後同じ。今回の描画ラベル数は長行65、通常1,799。通常の最後の表示対応は原文1,191,526行から40行、全体1,191,565行・7桁幅で、最後に描画したラベル範囲は1,191,559〜1,191,565となった。

[既存予算](../../performance-plan.md#8-長行の有界表示試作)の接続100ms・メモリ512 MiB以内で、同期移動100ms超もなかった。tick最大は16.7msを超えるため60fps達成とはしない。各1回であり、CPUや同期時間の低下を改善効果、メモリ増分の差を余白だけの保持コストとは断定しない。メモリは10msサンプル、割当/GCは計測器構築から報告前、CPUはより広いプロセス累積。物理描画/入力遅延・個別GC停止/LOH割当・Cold・検索速度・配布物起動は未測定。通常製品へ新たな起動/検索処理は追加していない。
