# 本文挿入の中間コピー削減

A-01-02。**候補は不採用とし、通常コードを変更前の文字列挿入へ戻した。** 対象はDocumentBuilder.Appendの挿入処理。[割当スタックの根拠](../2026-11-06-allocation-origins/README.md)に基づき、借用配列範囲を既存Ropeへ同期コピーし、同じTextDocumentへRopeTextSourceを挿入する候補を比較した。非配列メモリはその範囲だけ配列化した。レイヤ・公開API・Builder/Handleの型・保持モデル・所有/ReadLease・枠・Undo無効化は変えず、依存も追加していない。行別投影の未承認変更案A-03は実施していない。

## 正確性

DocumentBuilderCopyTestsの12ケースで、配列部分範囲/再利用、0/1/255/256/257/16,383/16,384/16,385文字、文字列/非配列メモリ、CRLF/サロゲート分割、行列、Undo/Redo不可、空Appendでの所有/破棄検査、ハンドル解放後のLease、1,048,579文字の借用チャンク再利用後の全文SHA-256を確認した。通常`./test-mac.sh`は.NET 689件/Python 57件成功。最初の所有テストはawait後に別スレッドへ移動していたため試験自体が失敗した。所有スレッドへ戻ったと仮定せず、同期待機して同じスレッドで破棄後検査を実施する形へ修正した。

## macOSの比較

変更前固定`f98f394`と、同基点+summary.json記載の製品ソースSHAの候補を別フォルダへビルドした。各バイナリSHAも保存。seed 20261106の50 MiB UTF-8を、各ホストで事前読取してWarmにし、変更前→候補を交互に各3プロセス×10操作、計60操作実行した。全操作は既存コア予算内で、入力SHAは実行前後で不変だった。プロセス起動と入力Warm化は構築時間に含めない。

割当は約40.9%減った一方、時間は約6.1%、CPUは約3.6%増えた。すべての性能が改善したとは判断せず、GC停止への効果とコストを記録する。メモリはphys_footprintの10 ms観測で、真の瞬間ピークや保持量ではない。非専用機の少数Warm結果であり、Cold、GUI、文法、検索、再読込や複数文書の合格にはしない。

## 候補の回帰と復元

候補`3cc8228`でも既存の50 MiB×5タブとReadLease走査の性能試験が各1件成功した。タブはCPU 2,968.113 ms、GC合計374.339 ms、OS増分約898 MiB、閉鎖後の弱参照0/10。走査は全30,980,684文字のchecksum一致、約29.5–37.8 ms/約32.7 KiB割当、GC停止0だった。生値は`retention.json`/`scan.json`。これらは候補の資源/走査回帰であり、実描画やコピー削減効果の証明ではない。CacheConditionの欄がunknownでも、タブ試験は測定前の独立厳格UTF-8文字数照合で入力をWarmにしている。

通常コードは変更前と同じ製品ソースSHAへ復元した。借用メモリ/Unicode/全内容ハッシュを確認する12テストは通常経路の回帰として残す。復元後もローカル.NET 689/Python 57件が成功し、`0a56cef`の[両OS CI](https://github.com/m-hiroaki/codeView/actions/runs/42184234581)も成功した。TRXを直接照合して追加12ケースは両OSすべて合格（macOS .NET689/Python57、Windows .NET686+既存Darwin専用3スキップ/Python37+既存POSIX専用20スキップ）。`restored-ci.json`にケース別結果・ZIP/TRX/環境のハッシュを保存。候補差分は`candidate.patch`とコミット`3cc8228`に保存し、通常経路への比較フラグや追加依存は残さない。

`local-runs.json.gz`に全60操作とホスト完了記録、`summary.json`に候補/復元ソース・バイナリ・入力・TRXのSHAと集計を保存した。元ログ・個別JSONは`artifacts/document-copy-comparison`へ保持する。CPU・メモリ・GCのトレードオフを評価して不採用とした比較タスクであり、GC予算未達の是正、G2の採用・長行描画・実機受入・A-01全体は未完了のままとする。
