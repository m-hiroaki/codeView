# 本文挿入の中間コピー削減

A-01-02。対象はDocumentBuilder.Appendの挿入処理。[割当スタックの根拠](../2026-11-06-allocation-origins/README.md)に基づき、借用配列範囲を既存Ropeへ同期コピーし、同じTextDocumentへRopeTextSourceを挿入する。非配列メモリはその範囲だけ配列化する。製品のレイヤ・公開API・Builder/Handleの型・保持モデル・所有移譲・ReadLease・処理枠・Undo無効化を変えず、新しい依存を追加しない。行別投影の未承認変更案A-03は実施しない。

## 正確性

DocumentBuilderCopyTestsの12ケースで、配列部分範囲/再利用、0/1/255/256/257/16,383/16,384/16,385文字、文字列/非配列メモリ、CRLF/サロゲート分割、行列、Undo/Redo不可、空Appendでの所有/破棄検査、ハンドル解放後のLease、1,048,579文字の借用チャンク再利用後の全文SHA-256を確認した。通常`./test-mac.sh`は.NET 689件/Python 57件成功。最初の所有テストはawait後に別スレッドへ移動していたため試験自体が失敗した。所有スレッドへ戻ったと仮定せず、同期待機して同じスレッドで破棄後検査を実施する形へ修正した。

## macOSの比較

変更前固定`f98f394`と、同基点+summary.json記載の製品ソースSHAの候補を別フォルダへビルドした。各バイナリSHAも保存。seed 20261106の50 MiB UTF-8を、各ホストで事前読取してWarmにし、変更前→候補を交互に各3プロセス×10操作、計60操作実行した。全操作は既存コア予算内で、入力SHAは実行前後で不変だった。プロセス起動と入力Warm化は構築時間に含めない。

| 構築時間ms | 401.153 | 425.448 |

割当は約40.9%減った一方、時間は約6.1%、CPUは約3.6%増えた。すべての性能が改善したとは判断せず、GC停止への効果とコストを記録する。メモリはphys_footprintの10 ms観測で、真の瞬間ピークや保持量ではない。非専用機の少数Warm結果であり、Cold、GUI、文法、検索、再読込や複数文書の合格にはしない。
