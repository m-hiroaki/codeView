## Warm読取

P0-06、seed 20261106の各50 MiB入力を使い、独立した厳格復号とSHA-256で全入力を事前読取した。各文字コードでbaseline/counted各3プロセス×10読取、合計12プロセス/120読取が成功し、終了後の入力ハッシュも一致した。

| 文字コード | 入力bytes | PrepareのAPI bytes | 消費のAPI bytes | 合計API bytes | 合計呼出し数 | 復号文字数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| UTF-8 | 52,428,800 | 52,436,992 | 52,428,800 | 104,865,792 | 1,603 | 30,980,684 |
| CP932 | 52,428,800 | 52,502,528 | 52,428,800 | 104,931,328 | 1,604 | 38,947,124 |

各値は1操作。BOMは両入力とも0。今回のCP932ではUTF-8の失敗検証64 KiBを含むため、UTF-8よりAPI読取量が多い。失敗位置が異なる入力へこの差を一般化しない。全行のmacOSプロセスdiskio読書き差分は0で、API読取量と区別する。

| 文字コード/モード | 10読取の時間合計中央値ms（範囲） | CPU合計中央値ms | OS問合せ1回の中央値µs |
| --- | ---: | ---: | ---: |
| UTF-8 baseline | 290.818（287.617–445.168） | 310.832 | 1.047 |
| UTF-8 counted | 287.335（286.986–432.195） | 304.945 | 1.012 |
| CP932 baseline | 562.168（562.029–570.079） | 575.671 | 1.046 |
| CP932 counted | 559.269（556.758–729.549） | 573.217 | 1.069 |

中央値は3プロセス間。両モードがOSカウンターを取得する。時間/CPUの区間には前後の問合せを含めず、問合せ負荷は10,000回を別測定した。分布の揺れがあるため高速化や負荷ゼロを結論しない。GUIやColdの性能予算は判定していない。

## カウンターの対照確認

採用macOS SDKへCのsizeof/offsetofで照合し、rusage_info_v2は160 bytes、disk read/writeは144/152を確認。既存Warm入力では通常読取もF_NOCACHE指定もdiskio差分0だった。次にO_EXCLで新規生成した50 MiBだけを対象に、書込側F_NOCACHE/fsync後、別プロセスのF_NOCACHE読取を行った。disk writeは52,428,800 bytes、disk readは50,331,648 bytes、API読取は52,428,800 bytesだった。生成パターンの独立SHAも一致した。

正のカウンターが取得できることを確認した範囲であり、全量Cold・機器レベル・ファイル別物理I/Oを証明しない。既存ファイルやOS全体のキャッシュ設定は変更していない。
