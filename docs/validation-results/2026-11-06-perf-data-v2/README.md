## 生成・独立検証

[preparation.json](preparation.json)に生成条件、seed 20261106、各manifest、全バイトの検証結果、独立した文字数・行数・一致数を保存した。対象の生成器/単体試験/preparationスクリプトはSHA-256で識別する。実データはソース管理外の/private/tmp/codeview-perf-v2-20261106の各currentRootにある。移動前のgeneratedRootは由来の記録として保持し、相対パス/内容digestと実際のcurrentRootを区別する。

合計15ケース、100,021ファイル、3,269,459,968 bytes（3,118 MiB）。生成後のverifyに加え、標準の厳格な増分デコーダーで全ファイルを再読取し、実バイト数・UTF-16単位数・CR/LF/CRLFの行数・チャンクをまたぐ一致数を独立に確認した。生成時は64 KiB以下の反復ブロック、検証時も64 KiB読取を使い、全本文をメモリへ載せていない。

L1はwide+mixed分布+深さ10を併用する。先頭50 MiB・次の1 MiB・残りの小ファイルを含む。直下は10,000ファイルと階層用フォルダーの計10,001項目。最深ディレクトリ10階層、全体のディレクトリ数89を別に記録する。

L2/L3はUTF-8/CP932別の計4条件をplannedOnlyに保存した。各20万/5 GiB、100万/20 GiBを、書込みせず期待行数/文字数/一致数・配置・分布まで計算した。L2/L3全データの実生成や性能試験を実施済みとは扱わない。生成方法の件数・サイズ式は単体試験でも全プロファイルを逐次検証した。

## 追加メタデータの検出と是正

最初のL1検証では想定外の.DS_Storeを9件検出し、50,009ファイルとして失敗した。保全時にはコレクションルート分を含む10件があり、ZIPへ保管して既知のメタデータだけを除去した。既存の生成データを/private/tmpへ移動して再検証したが、L1に9件の再追加を検出して再度失敗した。lsofの確認時点では書込み元のプロセスを特定できていない。

[unexpected-metadata.json](unexpected-metadata.json)に両試行のパス・ハッシュ・保全ZIPのハッシュを記録した。ソースファイルは削除/上書きしていない。既知のメタデータを保全した後、生成したコーパスのフォルダーだけをmode 0555にして新規追加を防いだ。resumeは既存の条件を照合し、全データを再読取検証した。追加ファイルを無視する例外をverifyへ導入していない。通常の作業フォルダー、製品の設定、OS設定は変更していない。
