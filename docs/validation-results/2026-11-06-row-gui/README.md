# 行別GUIの接続検証（2026-11-06）

A-03で承認された専用試作のA-04-02を、`1d7b10c1e05013d76f41b7bde23c8b2f6cf29435`で検証した。[行別GUI CI](https://github.com/m-hiroaki/codeView/actions/runs/42211188954)は両OSとも成功。[通常CI](https://github.com/m-hiroaki/codeView/actions/runs/42211188967)もmacOS .NET726/Python95、Windows .NET723+既存3スキップ/Python75+既存20スキップで成功した。追加した行別ポインターの単体7ケースと、記録照合のPython6ケースを含む。

## 実行内容と結果

長行混在（1 MiB長行+通常100行、1,049,976 UTF-16単位/103行）、空文書、Unicode/混在改行（1,250単位/151行）を、各OSで独立3プロセスずつ直列実行した。各OS9プロセス・閲覧位置変更576回・検証1,302件が合格した。

- 原文の文頭末尾・Shift選択・全選択のキーをネイティブコントロールへルーティングした。
- 行番号、切詰めの欄外表示、行ごとの選択背景の描画を確認した。表示専用LFをネイティブ選択へ含めず、背景Spanも原文との交差に限った。
- コピーキーは従来のCoordinator/原文Leaseを使用し、非空入力6プロセス/OSでネイティブClipboardから全原文を読戻した。CR/LF/CRLFを含む原文と完全一致し、失敗0件。通常AvaloniaEditのコピーが改行を正規化する既存評価とは経路が異なる。
- 閲覧位置だけを64回変更しても原文Anchor/Caretを保持し、画面外Caretから次のキーで復帰できた。旧投影拒否、原文不変、読み取り専用、Undoなしを照合した。
- 行数は現在の閲覧位置から要求行数（画面内の整数行）と残りの原文行数の小さい方に一致した。最大表示量はWindowsで898、macOSで808 UTF-16単位で、全プロセスで16,384単位以内。

ポインターの単体試験は省略された長行をまたぐ原文コピー、CR/LF/CRLF、投影交換をまたぐ逆方向の行選択、Shift/空行、他ポインター/他セッション/旧投影/サロゲート途中の拒否を確認した。物理ポインターによる捕捉/範囲外自動移動の統合受入は未完了。

## 性能値の扱い

このCIは機能接続の検証であり、A-05/G2の性能受入ではない。同期描画更新の最大はWindows 16.6527 ms、macOS 49.7157 msだった。Windowsの初回長行混在で接続1,126.2329 msを記録し、既定の接続100 msを超える。除外や予算緩和はしない。再現条件を含む大規模入力の性能検証へ持ち越す。

`AnimationTickIntervalsMilliseconds`は各更新後に**2回のAnimationFrame callbackを待つ**測定で、単一tickや物理描画時間ではない（最大Windows 93.7343 ms、macOS 155.6557 ms）。16.7 msの単一tick予算への合否換算には使わない。CPU/割当/GC/10 ms間隔のメモリサンプルは、起動・入力構築・全機能操作・Clipboard・検証用ハッシュ生成を含む試作全体の範囲である。UIなしのコア64取得試験と直接比較しない。全指標を`summary.json`とZIPに保持する。

通常表示のネイティブ回帰は[別CI](https://github.com/m-hiroaki/codeView/actions/runs/42211188905)で実行待ち。通常ビルドには今回のGuiProbeソースは含まれないが、この時点で当該回帰が成功したとは記載しない。

## 初回失敗と修正

`cc6025e`の[初回CI](https://github.com/m-hiroaki/codeView/actions/runs/42210918359)は両OSで長行混在が成功し、次の空文書で旧投影拒否の検証に失敗した。空文書の同一閲覧位置へのSetViewportは投影を無効化しないため、試験が現在の投影を旧投影と誤認していた。`1d7b10c`で同じ座標でも表示文書/投影を明示交換してから拒否を確認するよう修正した。通常の位置変更なしで投影を維持する契約は変更していない。先頭サロゲートのShift選択長もスカラー長で判定するよう補正した。失敗したZIPも保持し、最終合格回数へ混ぜない。
