# 原文行番号余白での行選択

A-02の下位作業A-02-01。専用GUI試作のみ。通常UIへの採用/G2/A-02全体は未完了。

## 実装と単体検証

原文のDocumentLineを使い、行番号余白から行全体を改行込みで選択する。長行の途中だけが表示されていても原文の開始/終了を使う。逆方向ドラッグとShift拡張、空文書/末尾空行、古いSlice/別ポインターの拒否、範囲外/解放後の不採用を12件追加した。通常Release602件合格、失敗/スキップ0。TRXはローカルの`artifacts/test-results/line-selection/unit.trx`。

行の開始/終了位置は改行・スカラー境界が確定しているため、一般の選択位置の補正に伴う遠い本文の文字読取を行わない。全文コピー、全行走査、追加Leaseはない。選択用のポインター状態は行Anchor/最後の対象行だけを追加し、文書や表示窓を保持しない。

## 反復性能

性能計画23章の事前予算を適用した。最初の10万反復は80,000,168 bytesの割当で1 MiB予算に不合格。行境界での不要な文字読取を省く修正後、[結果](line-pointer-cycles.json)は経過59.799ms・CPU59.071ms・割当168 bytes・GC停止0ms、セッションLease1/ポインター追跡なしで合格した。入力/描画/OSメモリ/起動/検索を測るものではない。前回の失敗JSONは再実行で上書きされており、失敗値は実行コンソールで確認した記録である。

## Mac専用GUI

`CodeViewPerformanceProbe=true`でReleaseビルドし、通常の製品には有界表示を採用していない。`CODEVIEW_GUI_WINDOWED=1`、`CODEVIEW_GUI_INTERACTIVE=1`、`CODEVIEW_GUI_VERIFY_CLIPBOARD=1`、`CODEVIEW_GUI_WINDOW_CHARS=1024`を指定した。入力は次をUTF-8へ保存したもの。全8,029 UTF-16単位・5行。

```python
text = 'first😀\r\n' + '// 注文😀 ' * 1000 + 'END\r\nthird\r\nfourth\r\n'
```

実画面とAXで次を確認し、Ctrl+CのコピーをOS読戻しで検証した。

| 操作 | 原文の選択/コピー |
| --- | ---: |
| 行番号3をクリック | thirdとCRLF、7単位 |
| 長行の途中を表示した状態で行番号2をクリック | 原文2行目全体とCRLF、8,005単位 |
| 行番号4→2へ逆方向ドラッグ | 原文2〜4行、8,020単位 |
| 行番号3→Shiftで4をクリック | 原文3〜4行、15単位 |
| 末尾空行5をクリックしてコピー | 選択0、コピー受付なし |

最初のCmd+C操作では全選択が入り8,029単位となったため、狙った行選択の証拠から除外した。Ctrl+Cでは上記の原文範囲が維持された。逆方向ドラッグ直後のShiftクリックは表示窓に目的行が含まれず選択が変わらず、クリーンなShift拡張は末尾へ移動後に実施した。Ctrl+Endは末尾へ移動したが追加の未対応キー診断も入り、キー受入の合格証拠にしない。これら診断操作も[生報告](interactive.json)に含む。

OS読戻しは全6回一致・不一致0（うち4回が上表の選択受入、他2回は診断操作）。PointerUpdates9、範囲外タイマー発火0、終了時PointerActive=false、Failure=null、Closed/CLI終了0。対話待ち時間を含むこのGUI実行の性能値は評価しない。入力・DLL・ソースのSHA-256は[provenance](provenance.json)。

初回の入力生成で手元PythonのPath.write_textがnewline引数を受け付けず入力が生成されなかった。初回GUIはopen-failed/Closed/終了1を確認後、write_bytesで生成して別の報告先で最終版を実行した。

実機後のレビューで、末尾空行と直前行の選択終端が同じ場合でも、対象行が移動した限り範囲外タイマーを継続するよう修正した。同オフセットを理由に縦移動を途中停止しないためである。既存の境界試験へ戻り値の検証を加え、通常602件合格と専用GUI最終ビルド警告0/エラー0を確認した。この分岐は今回実機では発火しておらず、実機DLLとレビュー後の最終DLL/ソースのハッシュをprovenanceで区別した。
