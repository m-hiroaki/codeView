# 通常行の可視行数を満たす表示窓の比較

A-02の下位作業A-02-02。連続範囲の既存Slice/原文選択を維持した専用試作。全面スクロール・通常UI採用・G2/A-02全体は未完了。

## 方法

DocumentDisplaySession.CreateViewportSliceは、指定位置の周囲1〜512行を原文の行索引から取得する。1行上限以下・全体16 Ki UTF-16単位以内なら原文行の開始/終了に揃えて返す。行末改行は切らず、末尾では前の行を補う。1行上限または全体上限を越えれば従来の文字数窓へ戻す。連続範囲なので長行を飛ばして後続行をつなぐことはしない。この限界を除去した方式ではない。

専用GUIは`CODEVIEW_GUI_VIEWPORT=1`と`CODEVIEW_GUI_WINDOW_CHARS=1024`を指定し、TextViewの高さ/DefaultLineHeightを切上げ、余裕2行を足した行数を要求する。初回接続・対話移動・自動移動・選択表示に同じ切出しを使う。対話中はSizeChangedを購読し、切替/終了で解除する。原文位置/選択/コピー/行番号の契約は維持し、追加の原文Leaseや全文複製を作らない。

## 単体と取得性能

通常622件合格・失敗/スキップ0。追加20件はCR/LF/CRLF、通常行の可視行数/原文対応、末尾/空/短文書、長行/全体上限のフォールバック、旧Slice拒否、最小1/最大512行、不正範囲/閉鎖/サロゲート境界を確認。ローカルTRXは`artifacts/test-results/viewport/unit.trx`。

性能計画24章の事前予算で、構築後の10万短行から80行を1,000回取得した。[結果](viewport-slices.json)は経過20.9595ms、CPU21.17ms、割当2,664,280 bytes、GC停止3.148ms、最大1,200単位、Lease1で予算内。GUI/OSメモリ/起動/検索を測るものではない。

## 実画面とサイズ変更

生成したnormal.csは1,001行（末尾空行込み）。各行は次の77 UTF-16単位、全77,000単位。

```python
text = ''.join(f'// line {n:05d}: ' + 'sample = 123; 注文😀; '*3 + '\r\n'
               for n in range(1, 1001))
```

Mac実画面で1180×800 DIPの通常サイズを表示し、最下部まで本文/原文行番号があることを確認した。標準の拡大操作でウィンドウを大きくし、元サイズに戻しても画面を満たした。PageDown（CUAのNext）で原文26行1列へ進み、原文番号2〜26が表示された。ドラッグによる初回サイズ変更は変化がなく、拡大/復帰操作の結果で判断した。CUAのPageDown指定はkeyNotFoundとなり、Nextで再実行した。

[対話生報告](interactive.json)の要求行数は36→41→36、表示行数37→42→37、最大3,157単位。行末改行に続く空行を数えるため表示行数は要求より1大きい。絵文字を含む実レイアウトではDefaultLineHeightによる推定より表示行が少なく、要求は25〜29可視行を十分満たした。この推定を全フォントの厳密な可視行数保証にはしない。

最初の画面取得ツールの応答は44,706.33秒遅延した。既存のexecハンドル48313で実行継続を確認し、再起動せず同一プロセスで検証・Closed/終了0まで確認した。対話待ちを含むこの実行の性能値は除外する。終了時Failure=null。画面の状態は対話で確認し、画像ファイルは保存していない。

## 固定ビルドでの自動比較

同じDLLで固定文字数窓/可視行数窓を各1回、新プロセスで順次実行した。通常UTF-8 50 MiBと単一長行50 MiBは既存生成物、小入力は上記normal.cs。入力全読込でWarmを準備し、64回移動・訪問65・Closed/終了0・Failure=nullを確認した。最後のGUI測定は04:07:11 UTC、最終単体試験は04:07:31 UTC開始で重複しない。64移動の同期時間とtick間隔は物理描画/入力遅延ではない。

| 入力/方式 | 接続ms | 同期移動最大ms | tick最大ms | メモリ増分MiB | CPU ms | 最終表示行数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 通常50 MiB/固定 | 7.446 | 7.258 | 17.737 | 351.88 | 1996.928 | 40 |
| 通常50 MiB/可視行数 | 7.995 | 11.289 | 17.351 | 330.16 | 1997.060 | 36 |
| 長行50 MiB/固定 | 11.354 | 11.276 | 17.657 | 279.38 | 1173.929 | 1 |
| 長行50 MiB/可視行数 | 11.528 | 10.488 | 17.743 | 293.78 | 1164.522 | 1 |
| 小入力/固定 | 15.537 | 11.657 | 28.575 | 210.36 | 991.674 | 15 |
| 小入力/可視行数 | 16.263 | 13.175 | 29.580 | 215.81 | 1306.430 | 36 |

接続100ms/メモリ512 MiBの予算内だが、全条件tick16.7ms目標は未達。小入力は表示量増加に伴い割当45,267,032→95,000,992 bytes、CPU991.674→1306.430ms、GC停止21.332→46.461msに増えた。固定窓の15行から36行を描くコストであり、無条件の性能改善や採用根拠にはしない。各1回なので差を再現性のある改善/劣化幅と断定しない。

通常50 MiBはもともと短い行が多く固定窓でも40行あり、可視行数要求36行を満たすことによる描画増加はない。単一長行は要求36行に対して表示1行・最大1,024単位で、描画上限を維持した。長行混在での行数不足や全体上限超過は未解決。

[集計](summary.json)、同名の各JSON/ログ、[DLL/ソース/入力ハッシュ](provenance.json)を保存した。最初の比較スクリプトは長行のパスを通常階層の形で指定して失敗した。先の通常2回は正常終了済みで再実行せず、正しいパスで残り4回を別名へ実行した。GUI初回ビルドのnull許容エラーは修正し、最終版は警告0/エラー0。Cold/個別GC停止/LOH割当・物理I/O/CPU使用率・配布物起動・検索は未測定。
